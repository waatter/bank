# TROPOS 后端安全报告只读复核

日期：2026-11-02。依据当前工作区代码和 `.local/security-report/original.txt` 中的《安全自评报告》，重点审阅 `backend/server.py`、`service.py`、`agent_ops.py`、`model.py`，少量查看模型配置实现。代码行号指当前工作区，不保证等同原报告列明的提交。静态审阅；未运行测试、未对外发请求、未进行渗透测试，也未核实原报告的测试数量、部署环境、购物连接器或前端。严重度针对声明的演示部署，不代表生产认证。

## 关键发现

### 高：局域网口令可通过伪造 Host 绕过

`TroposHandler._guard`（`backend/server.py:183-193`）允许 localhost、127.0.0.1 等 Host，并仅凭该请求头决定 `_loopback_request`；`_dispatch`（`server.py:299-304`）对被标记为 loopback 的请求跳过 `X-Tropos-Access`。当服务绑定 `0.0.0.0` 且配置局域网口令时，同网设备可直接连接局域网 IP，同时自报 `Host: localhost:<实际端口>`，省略 Origin 和口令，即可通过这层检查。Host 不是可信的客户端来源；匿名登录接口及共享演示会话因而可访问。代码推导，不涉及真实网络实测；不等于自动取得注册用户会话。建议按实际连接来源及可信代理边界验证，或对所有网络请求统一检查口令，添加远端连接伪造 Host 的回归测试。

### 中：开启模型管理开关不等于具备管理员身份

`TroposServer.__init__`（`server.py:126`）将 `model_admin` 作为进程级开关；模型提供方配置路由在普通 `_user()` 会话认证之后调用 `configure`（`server.py:345-347,421-430`）。`ModelCenter.configure`（`backend/model_center.py:286-292`）检查开关而非管理员角色。开关一旦打开，任何有效会话，包括可匿名取得的共享演示会话，都可配置进程级模型。此风险取决于显式开启该选项；默认关闭。原报告 L5“可信管理员”应改为“开启后任何已认证用户”，并强调仅限完全可信环境。建议独立管理员凭据或彻底移除在线平台配置。

### 中：多步骤执行可绕过规划时的理财锁定检查

`AgentOps._step`（`agent_ops.py:357-364`）在规划赎回时检查当时持仓锁定期；同一任务可以先申购后赎回，而 `AgentOps._execute`（`agent_ops.py:540-552`）申购后写入新锁定期，赎回时却只检查余额，不重新检查锁定期。若规划时存在未锁定持仓，随后任务中先申购同产品再赎回，执行时可赎回已被最新申购重新锁定的持仓。这与 `_holdings`（`agent_ops.py:120-129`）按最近申购锁定全部持仓的演示规则冲突。需要重新读取持仓锁定状态后执行赎回，并覆盖同单先申购后赎回的测试；此为代码层条件路径，未动态复现，实际资金为合成数据。

## 对原报告的逐项核对

- **认证与隔离**：`BankService.register`（`service.py:355-386`）创建独立用户并复制样例；`session`（`service.py:587-594`）为同一 persona 重用共享演示用户，报告 R01 的共享限制正确。`_new_session` 和 `authenticate`（`service.py:285-290,596-602`）使用随机令牌、摘要与 24 小时有效期；注册用户名存在时返回独立错误（`service.py:371-376`），因此“减少账户枚举”仅适用于登录错误，不是全局防枚举。登录限流按账户而非全局来源（`service.py:388-415`）。
- **CSRF / Host**：`_guard`（`server.py:182-198`）要求单个允许的 Host、若存在 Origin 则须同源并拒绝 cross-site；`_body`（`server.py:245-269`）要求 JSON 与限长，`_bearer`（`server.py:270-280`）要求显式 Bearer。它们有助抵御普通浏览器跨站请求，但允许无 Origin、Host 可由非浏览器客户端伪造，不能作为网络身份认证。没有据此证明可从任意第三方网页直接读取受保护数据。反向代理、HTTPS 和 CSP 的实际部署未核实。
- **读取同意**：原报告“所有账本读取……要求 readConsent”过宽。`session` 和 `register` 在未见 `_consent` 检查时直接返回 `_snapshot`（`service.py:382-386,587-594`）；因此应区分基本账户快照与需要同意的分析/操作。`_consent` 本身位于 `service.py:228-230`。
- **转账授权和幂等**：`BankService.confirm`（`service.py:887-924`）按用户取方案、核对确认令牌，检查 revision、过期、生活计划和实时财务条件，并以方案 ID 查询已有交易、事务内记账。调用方 key 跨资源复用会被拒绝。已结算重试先返回既有交易，发生在版本和过期检查之前，属于重放回执而非重复执行。该结论仅覆盖此转账路径，不能推广至所有支付或外部订单。
- **事务与多步骤**：`_db`（`service.py:195-211`）异常时回滚；但 `AgentOps.confirm`（`agent_ops.py:493-515`）将业务失败表示为返回值，已成功步骤会提交，后续步骤暂停。这与报告 §7.2 一致，却与 §5.2 无限定的“失败整体回滚”矛盾。应明确区分异常回滚与业务失败保留先前成功步骤。它用一个任务令牌和一次请求中的步骤 ID 列表授权（`agent_ops.py:468-490`），不应概括为每步独立令牌。
- **模型与数据流**：`model._llm_json`（`model.py:719-731,757-761`）把用户原始消息及可选准备好的上下文发往配置的模型端点；用户自行输入的账号、令牌或敏感备注仍可能进入原始消息，因此报告“账号、会话令牌和 API Key 不发送”只能限定为系统不主动从内部状态添加这些字段，不能保证用户文本无敏感信息。`agent_response`（`model.py:2147-2184`）对转账检查原消息和模型收款人是否匹配，并生成待确认草案；未发现该路径直接调用转账确认。不能仅凭提示词或正则断言所有提示注入均被阻断。
- **供应商边界**：`_llm_json` 接受 HTTPS 自定义主机及本机 HTTP（`model.py:721-725`）；`_research_kimi` 用包含 `kimi` 或 `moonshot` 的主机名识别（`model.py:921-927`），并非固定官方域名。自定义端点可能是产品功能，但报告“固定供应商”不宜一概而论；端点控制者可接收发送给该端点的消息和对应 API Key。是否构成 SSRF 还需结合配置校验、DNS、网络策略和部署核查。

## 结论与未验证范围

原自评对共享演示账户、合成资金、独立认证令牌与部分执行的限制有说明；但“主要控制闭环”需要纳入 Host 口令绕过及模型管理开关权限条件后重新评估。优先修复局域网口令绕过，再处理模型管理授权与任务内锁定期复核。购物、邮件、外部服务、代理配置、测试统计和其余模块不在本次完整审计范围内，不应将本报告视作对它们的通过结论。
