# TROPOS：争冠路线与动态画像设计

更新：2026-10-21。本文区分当前已运行的能力、可复核证据和下一步工作，不预判比赛名次。启动与复跑命令见 [README](../README.md)。

## 当前作品的主线

赛事官网将国内人工智能方向描述为在安全框架内，通过自然语言理解、规划并执行银行业务，强调安全和体验。现有材料没有可核实的具体评分权重，因此不编造评分比例。[官方赛题说明](https://fintechathon.g-ican.com/)

作品围绕一条行动链展开：用户确认画像，模型理解请求，服务端给出有依据的计划；事件发生后重算现金和任务状态；用户再单独确认具体操作；服务端核验、记账并返回可追溯的合成回执。“三扇窗”呈现这些差异，账本与记录支撑这些差异。

本轮已从浏览器交互样例推进到本机银行沙箱。Python 标准库 HTTP 服务提供受限页面路由和业务接口，SQLite 持久保存画像、合成账户、复式分录、方案、授权和审计；多线程请求使用独立数据库连接，事务由领域服务处理。源码由 GitHub 管理，尚未部署多人远程共用的云服务。

## 用户画像的三层结构

| 层 | 内容与来源 | 更新方式 | 对行动的影响 |
|---|---|---|---|
| 用户确认的选择 | 当前目标、目标金额、现金底线、收入稳定性声明、表达风格和服务偏好 | 用户编辑并确认，记录版本与来源 | 影响策略侧重和现金约束；表达风格不改变资金权限 |
| 财务事实与短期状态 | 当前余额、账单、订阅、预计收入、已到账收入、既有任务状态 | 由明确的合成账本事件触发 | 重算现金路径，使过期方案需要重新核验，区分等待条件与等待确认 |
| 推断和策略 | 现金缺口、策略侧重、建议上限与待核对事项 | 按当前快照和可解释规则重算 | 说明依据；推断不会产生执行授权 |

用户不必每次登录重答问卷。长期目标和现金底线仍由本人修改，偶发消费不会自动改写长期画像。未来若增加长期习惯推断，应展示证据、观察窗口与更正入口，并先提出待确认建议。

首次读取同意由用户主动勾选。服务端在取得同意后才允许草拟转账、模拟账本事件和订阅取消；请求资金计划时，未同意的账户只收到建档提示，不生成个人财务方案。用于模拟账户建档预填的快照沿用原有接口含义，不代表付款授权。

`ETHOS-R1` 根据用户目标、收入波动声明、现金缺口、债务压力与收入事件分配策略权重。百分比不是风险概率或模型置信度。用户目标、现金底线、读取同意与单笔操作确认相互独立，事件不会自动开启消费守护或增加付款权限。

## 本轮已落地的能力

### 模型理解与确定性规划

服务端适配 OpenAI 兼容 `/chat/completions`，通过项目本地 `.env` 或环境变量配置密钥、模型和地址，默认 `deepseek-flash`。未配置时显示规则模式；上游超时、截断或输出不合法时显示明确降级，不伪装为模型回答。服务端不向模型发送既有账本、历史交易备注、会话令牌或账户凭证；用户主动输入的消息（含转账附言）会发给配置的模型。

模型输出动作与字段经过独立白名单校验，只能查看、规划、澄清或草拟转账；不能确认、执行或触发账本事件。收款人必须匹配已登记账户，同名联系人需用户消歧。

资金计划由服务端快照确定性生成，附 `METIS deterministic rules` 来源，展示用户实际目标、现金底线、30 天最低余额与余量、必要账单、到期债务和既有任务。建议上限同时受已到账余额、现金底线与未来现金路径约束，不使用模型自由生成的金融计算；有缺口时明确不新增非必要转出，不宣称取消必要还款或未经确认延期。

例如当前合成输入中，阿林正常状态未来最低 ¥11,167、底线以上余量 ¥3,167；因其收入波动声明，本轮规则建议上限为 ¥1,000。陈工最低 ¥15,709、余量 ¥7,709，建议上限 ¥2,000。阿林工资延期后则出现 ¥2,524 缺口，上限降为 0。上述金额只对应当前合成快照和规则，不是投资建议或模型预测精度。

### 服务端授权、账本与回执

转账先生成带版本、确认凭证和有效期的方案。用户单独确认后，服务端重新核对收款人、单笔限额、当前余额、现金底线、未来账单路径及工资条件。画像或账户修订变化会使旧方案失效；确认凭证不匹配、已撤销或已过期的方案不能执行。

账款按整数分计算，交易与对应复式分录处于同一事务。重放同一方案返回原交易，不重复扣款；服务重启仍可读取账本和按凭证查询。超时演示先完成事务，再只返回 `UNKNOWN` 与原凭证，后续查询取回已存在的结果，不新建付款。

转账页可恢复本人最近 50 个持久方案。读取按当前账户修订、凭证期限、条件和实际交易记录派生状态，仅仍可确认的方案返回确认凭证；已记账方案关联原交易回执，过期或失效方案填回表单后须重新检查。恢复接口不改账、不续期，不把工资到账后的旧方案直接变为可执行。前端拒收跨账户和乱序读取结果，确认框限制键盘焦点并隔离背景操作；这些交互状态有替代 DOM 检查，仍需浏览器验收。

HTTP 模式中，SQLite 是业务状态的依据。浏览器调用同源接口，服务端限定回环 Host/Origin、Bearer 模拟会话、JSON 类型和长度，静态路由只允许明确登记的页面与样式脚本，不暴露项目文档、密钥、测试或数据库。这里的 A/B/C 选择是模拟账户入口，没有生产身份认证能力。

### 事件更新与任务生命周期

工资延期、新增维修账单、工资到账、已确认转账和订阅取消均触发财务状态与策略重算，保留事件来源和前后变化。工资到账只记一次，同时移除该笔预计收入；取消订阅在服务返回合成取消回执后才移除未来续费。

预计工资从未当作当前已到账余额。工资延期不自动降低日常预算，也不自动延后必要账单。现有工资依赖任务在条件满足后只恢复为待确认；若要执行，用户仍需依据最新状态重新生成方案并逐笔确认。当前没有后台自动执行器，不会自动转账、提前还款或申购产品。

未确认的意向仅展示，不计作正式已授权支出。未来若加入真正的定时执行与额度授权，必须另行实现授权范围、撤销、条件复核、正式任务预留和失败恢复，不能把现有待办展示等同于自动执行。

### 前端样例与购物边界

通过 HTTP 打开工作台时，账本、画像、转账和订阅操作以服务端返回为准；服务不可用时停止操作，不退回到本地模拟成功。直接以 `file://` 打开则仍是浏览器规则样例，支持时使用 localStorage 保存；两种状态不相互同步。

“先别买”继续展示付款后的现金影响、分期示例成本与主动开启/撤销的冷静期守护。它目前只提供前端建议，没有银行或商户支付拦截能力；购物放弃金额是拟避免支出，不是已经存入的资金。“陌生人陪审团”全部由本地规则生成，没有真实用户参与。

## 已取得的证据及边界

### 真实模型检查

本轮以 `deepseek-flash` 真实 API 验证了自然语言请求到合成银行待确认转账草案的链路。该次检查没有确认交易，没有扣款，见 [脱敏记录](../reports/model-smoke.json)。实际确认、超时查询和幂等记账是另由 HTTP 集成测试验证的链路，不将两者拼接为一次模型自动付款证明。

模型可调用不等于模型能力已有系统评估。现有模型回归主要使用本地模拟响应，覆盖字段注入、非法动作、金额校验、截断、超时、明确降级与同名收款人澄清；它们不度量跨表达理解准确率或真实用户任务完成率。

本轮新增 41 条固定自然语言任务，保留[修复前规则记录](../reports/intent-rules-before.md)和[当前结果](../reports/intent-rules.md)。实际发现了千位分隔、万元单位、中文金额、时间条件、备注及缺少上下文时的错误处理。规则解析和共享澄清入口按这些发现修复，预期保持固定。对话历史尚未接入，不能用更正或代指消息直接生成新转账；不支持的调度条件应澄清。任务集只调用理解和草拟，未确认交易；默认不调用付费模型。真实模型批量任务检查仍未运行，已知用例的通过也不表示未知表达可泛化。

### 规则策略对照

[对照报告](../reports/evaluation.md) 和 [逐场景 JSON](../reports/evaluation.json) 使用 48 个预先定义场景、144 次独立运行：3 位合成用户 × 4 种事件 × 4 个请求上限，分别运行固定规则、静态画像与动态画像。每个策略使用全新临时数据库，但共享相同输入和 ARGOS 安全网关。评分用独立整数分计算核对逐日路径、最低余额与参考可行上限，保存输入和源码指纹。

该实验没有调用模型。动态策略读取已知的事件后数据，其任务目标与参考可行上限一致，因此结果说明重算与服务执行是否相符，不能说明模型泛化、真实银行接入或降低逾期率。共享网关产生的共同零新增违规不能包装成动态画像独有的安全优势；容量为 0 时选择不转，也不代表原有缺口已修复。报告保留拒绝实例、原有缺口和计算假设。

### 自动化核验与未验收范围

Python 测试覆盖持久账本、事务、授权与幂等、用户隔离、会话有效期、HTTP 安全入口、并发确认、模型校验和评估口径。Node 检查覆盖浏览器本地业务不变量、真实 HTTP 客户端到工作台状态的衔接，以及会话恢复和过期处理；衔接检查以替代 DOM 运行，不等于真实浏览器点击测试。

当前尚未完成真实浏览器视觉、窄屏、完整点击路径、离线字体和演示录像验收。所有银行账户、金额、账单、交易与回执均为合成数据；模拟登录不具备生产认证；没有真实银行执行证据，也未部署云服务。

## 建议的三分钟主线

1. 0:00–0:25：进入模拟账户并确认画像，展示当前目标、现金底线与依据。
2. 0:25–0:50：同一句两万元请求，比较阿林与陈工的真实合成数字和确定性方案。
3. 0:50–1:25：工资延期，展示缺口、来源记录和待条件任务，说明目标与底线不会自动改变。
4. 1:25–2:05：切到现金条件允许的账户，草拟安全小额转账，逐笔确认后模拟超时，按原凭证查询回执，再重放验证只扣一次。
5. 2:05–2:30：工资到账，指出任务只是恢复待确认；需要执行时须重新生成方案并确认。展示订阅取消与画像同步更新。
6. 2:30–3:00：快速展示购物建议的前端边界、审计追溯与实际规则报告；区分模型草拟检查和规则对照证据。

## 复跑命令

```sh
./scripts/run.sh
```

另开一个终端，在项目目录运行：

```sh
python3 -m unittest discover -s tests -p 'test_*.py' -v
node tests/profile-invariants.cjs
node tests/backend-client.cjs
node --test tests/client-session.cjs
node --test tests/modal-accessibility.cjs
python3 -m eval.benchmark --output reports/evaluation.json
python3 -m eval.intent_benchmark
```

这些测试不调用付费模型 API，规则评估也不调用模型。真实模型检查按需单独进行，并分别记录是否只到草案、是否确认、是否实际记账。
