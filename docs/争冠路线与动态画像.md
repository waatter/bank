# TROPOS：争冠路线与动态画像设计

更新：2026-10-20。本文记录本轮产品判断、已经完成的改动与尚需实现的能力，不预判比赛名次。

## 用一条可核验的行动链组织作品

赛事官网将国内人工智能方向描述为在安全框架内，通过自然语言理解、规划并执行银行业务，强调安全和体验。官网没有在本轮检索中提供可核实的具体评分权重，因此不据此编造评分比例。[官方赛题说明](https://fintechathon.g-ican.com/)

“三扇窗”适合作为记忆点。接下来需要让评委看到：一个新用户如何形成画像；事件发生后哪些判断发生改变；为什么某项操作可以执行或应被暂停；执行后账本和预测如何保持一致。

## 用户画像的三层结构

| 层 | 内容与来源 | 更新方式 | 对行动的影响 |
|---|---|---|---|
| 用户确认的选择 | 当前目标、目标金额、现金底线、收入稳定性声明、表达风格 | 用户编辑并确认；修改留记录 | 影响策略侧重和现金约束；表达风格不改变资金权限 |
| 财务事实与短期状态 | 余额、账单、订阅、预计收入、已到账收入、待执行计划 | 账户/工具事件触发更新 | 重算现金路径、暂停失效计划、要求执行前复核 |
| 推断和策略 | 现金缺口、策略侧重、可疑行为模式 | 依据可复核规则或有证据的推断重算 | 给出解释；不把推断当授权 |

余额和账单等状态应随事件更新；不必每次登录重答问卷。长期目标可在用户有新计划时更新，行为习惯变化应先提出待确认建议。单笔偶发消费不足以自动改写长期画像。操作授权需另行明确取得、可撤销，不能由画像权重推导。

## 本轮已完成

- 模拟登录入口与三步 Financial DNA Scan：目标、现金预留、收入稳定性、表达风格和服务偏好。首次读取同意由用户主动勾选。
- 提交前显示初始策略和现金预测；工作台有“画像”页，可编辑、查看依据及更新记录。
- `ETHOS-R1` 根据目标、收入波动声明、现金缺口、债务压力与收入事件计算策略侧重。百分比是规则分配的权重，不是风险概率或模型置信度。
- 工资延期、新增维修账单、工资到账、转账与订阅取消均触发状态和策略更新，保留事件来源与前后快照。
- 工资到账只记一次，并移除同一笔预期收入，避免双计。事件不会自动降低现金底线、改目标或开启消费守护。
- 订阅续费纳入现金路径，收到模拟取消回执后才移除。已执行转账与工资到账回写模拟流水。
- 本人目标转账也检查主账户流动性。确认前表单或账户修订变化会使旧确认失效，同一凭证不会重复记账。
- 用户采纳预算建议不等于账单方同意延期；收到单独模拟确认后才更改正式预测日期。
- 购物放弃金额记为拟避免支出；拟留存与实际已存进度分开。目标改名不抹除已存资金。
- 支持浏览器本地保存模拟会话与重置当前账户。此保存依赖浏览器 localStorage 可用，不是服务端持久账本。

## 下一阶段按此顺序推进

| 顺序 | 要补的内容 | 可验收的结果 |
|---|---|---|
| 1 | 模型与服务端银行沙箱 | 自然语言生成结构化意图；授权、余额计算与交易结果由服务端强制决定；前端不能绕开 |
| 2 | 持久账本和任务生命周期 | 交易、复式分录、幂等凭证、授权版本和状态查询关联；服务重启后可核对；超时先查询原交易 |
| 3 | 动态策略的对照评测 | 固定同一批用户、工具与冲击，比较固定规则、静态画像、动态画像；报告实际样本量、失败例、约束违规和重规划结果 |
| 4 | 演示完成度 | 首次体验、画像更正、异常恢复、空态、窄屏、离线字体、重置、演示录像完整验收 |

“先别买”围绕付款后的现金路径、分期成本和用户主动选择来展示。模拟陪审团放在辅助位置；不把规则生成的投票描述成真实用户意见，不把原型守护说成已接入银行支付拦截。

## 建议的三分钟主线

1. 0:00–0:25：进入模拟账户，确认目标和现金底线，展示依据与策略。
2. 0:25–0:50：同样 2 万元任务，比较两种财务状态产生的行动差别。
3. 0:50–1:30：收入延期，查看画像前后记录、现金缺口与暂停的任务；长期目标仍在。
4. 1:30–2:10：确认取消低使用订阅或安全转账，展示回执、流水、预测和画像同时更新。
5. 2:10–2:40：评估一笔分期购物，指出影响哪笔支付，用户选择冷静期或撤销守护。
6. 2:40–3:00：打开日记追溯来源、规则、用户确认与结果；只展示实际测得的对照指标。

## 本轮核验与限制

`node tests/profile-invariants.cjs` 通过 16 项业务不变量检查，覆盖同意、现金底线、订阅、账单延期、金额更改、幂等、到账去重、状态恢复、目标改名与文字转义。另完成三个 JavaScript 文件语法检查和 Git 空白检查。

这不是浏览器端到端测试或比赛基准评测。内置浏览器的自动访问策略拒绝 `file://` 页面，因此本轮没有做视觉与点击流程验收，也未用其他浏览器手段绕过限制。首次体验与窄屏布局仍需真实浏览器验收。

当前仍是规则与合成数据驱动的浏览器原型：模拟登录不具备真实认证，尚未接入大模型、银行接口或服务端授权网关。比赛前必须补完服务端执行链，并据实际运行记录更新能力声明。
