# TROPOS 3.2.1 热修复说明

## 修复范围

3.2.0 的邮件服务会正确生成 `/demo.html?verify=...` 与
`/demo.html?reset=...`，但 HTTP 网关把所有查询参数都判为非法路径，
导致邮箱验证和找回密码链接返回 `INVALID_PATH`。

3.2.1 让 `demo.html` 可以接收网页实际使用的四类启动参数：

- `verify`：邮箱验证的一次性令牌；
- `reset`：密码重置的一次性令牌；
- `access`：局域网演示访问口令；
- `director=1`：演示导演面板开关。

## 安全边界

- 只有 `GET` 和 `HEAD` 请求可以携带上述参数；
- 只有 `/demo.html` 可以携带查询参数，API 和其他静态文件仍然拒绝查询参数；
- 参数名、长度和字符集逐项校验；
- 拒绝未知参数、重复参数、百分号编码别名和同时出现的验证/重置令牌；
- 验证令牌仍只通过 POST 接口消费，静态页面只负责安全启动前端流程；
- 请求路径和令牌仍不写入服务日志。

## 升级影响

本次不修改数据库结构，不轮换认证主密钥，也不改变 SMTP、模型或美团连接器配置。
升级时继续挂载原有 `/opt/tropos/deploy/data` 与 `.env.production`，现有用户、账本、
MFA 绑定和服务授权可以保留。3.2.0 中已经过期的邮件链接需要在账户页面重新发送。
