# TROPOS 3.2.9 千问稳定性热修复

## 本次修复

- 千问普通自由对话改为一次稳定的非流式请求，不再在同一轮中先开启思考模式、失败后再兼容重试。
- 千问普通对话固定关闭 `enable_thinking`，避免隐藏思考内容占满输出额度而没有可见回答。
- 模型中心的“测试连接”改为一次最小只读对话，不再先做结构化理解、再做自然语言回答。
- 千问上游失败后直接使用本地只读规则，不再悄悄发起第二次模型请求，降低超时和偶发失败概率。
- 浏览器将模型测试、普通银行助手对话等只读请求与转账、支付、下单类请求分别提示；只读超时不再显示“请查询原交易状态”。

## 安全边界

千问、DeepSeek、OpenAI、Kimi 等模型仍只负责理解、规划和只读回答。转账、付款、下单、取消和账户修改不会直接交给模型执行，仍由 TROPOS 服务端校验并要求用户逐项确认。

## 服务器更新

使用 `deploy/docker-compose.update-3.2.9.yml` 覆盖文件启动镜像 `tropos-candidate:3.2.9-20261101`。原有 `.env.production`、数据库和美团授权目录保持不变。

更新后可检查：

```bash
curl -fsS http://127.0.0.1:8765/api/health
```

返回的 `version` 应为 `3.2.9`。
