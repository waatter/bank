## 演示前准备

1. 核对 `/api/health` 为 3.0.0，页面与字体均从同源加载。提前检查是否为规则模式，若需模型须在服务器明确配置；实验对照通道可用不等于工作台已配置模型。
2. 使用独立的合成演示数据库。先自查必要订阅仍有效、账户可执行指定金额。多人共享公开沙箱会改动同一账本，应按场次协调，不冒充已具备真实租户隔离。
3. 现场主链以已验收的本地服务或同一局域网为备用，事先实测手机能访问；校园客户端隔离会影响局域网。实际公网仍按手机 Wi-Fi/蜂窝、关闭 VPN 的矩阵验收。
4. 当前韩国域名存在 TLS 建连失败记录，未完成服务器控制台诊断前，不把它作为唯一演示入口。按《手机与部署验收》检查源站、Caddy、证书与网络，不关闭证书验证。

## 遇到网络故障

保持原事项标识，先查询办理结果或恢复记录，不另发一笔确认。断网横幅只说明连接状态，不代表业务失败；恢复联网不会自动提交金融变更。整页无法加载时，页面内的断网提示也无法修复建连故障，应使用事先已验收的备用入口。

详细证据与未完成项以 [验收总表](3.0_验收总表.md) 为准；实际真人试用由本人同意后使用 `study.html`，内部演练与自动测试不计真人结果。
