# 3.0 手机与部署验收

## 当前边界与交付状态

目标是更新现有韩国实例 `demo.troposagent.com`，通过云平台已授权控制台管理。本地没有 Docker，也没有已授权 SSH 凭据；本轮没有部署到服务器、修改线上 DNS、购买或更换云主机。只读检查器不创建会话、不调用任何 POST/PUT/DELETE、不变更账本、不执行页面 JavaScript，不保存 cookie/token、响应正文或真实用户信息。

Dockerfile 保留原有 `COPY VERSION` 修复，并补入 `study.html`。Compose 使用隔离的 `deploy/build-context`；回环监听、只读根文件系统、`/tmp` tmpfs、SQLite `/data` 持久化及 Caddy 代理保持现有边界。模板检查与真实容器运行必须分开：本机无法确认镜像可构建、Caddy 实际加载成功、挂载权限或重启持久化。

截至本轮，专用本地测试已包含真实后端三页与资源读取，并核对运行前后的临时 SQLite 全部逻辑内容不变。既有 `reports/v3-local-readiness` 首份报告保持原样；它只证明当时的本地 GET。公网 TLS 失败保留为失败；本地 `study.html` 返回 200 只属于本地证据，不能证明公网可达。后续观测必须使用新目录，不回写首次结果。

## 只读检查器

从根源码目录运行，Python 3.10+，不需要额外依赖：

```bash
python3 scripts/v3_readiness.py https://demo.troposagent.com \
  --output deploy/readiness-public-run01
```

在服务器控制台同时比较公网与源站；该命令仍只有 GET：

```bash
python3 scripts/v3_readiness.py https://demo.troposagent.com \
  --origin-url http://127.0.0.1:8765 \
  --output deploy/readiness-console-run01
```

本地测试可用已经运行的 `http://127.0.0.1:8765`。HTTP 只允许字面 `127/8` 回环地址，不接受公网 HTTP、`localhost`、访问口令或查询参数；`--origin-url` 同样仅允许字面回环地址。URL 入口只接受站点根、`index.html`、`demo.html` 或 `study.html`，检查统一从站点根开始。

检查范围：

- `GET /`、`GET /demo.html`、`GET /study.html`、`GET /api/health`。
- 页面声明的同源脚本、样式、图像、图标、预加载资源；递归 CSS `@import`、`url()` 及字体；字面 ES 模块导入。循环去重；WOFF2 另核对签名。可安全解析的内联样式/SVG 引用也纳入。
- HTTP 200、资源 MIME、完整响应长度、`Cache-Control: no-store`、`Age` 缺省/0；记录首字节及完整响应耗时。当前应用统一 no-store，此策略下出现长期缓存视为失败，不能靠旧缓存掩盖发布缺件。
- health 要求 `ok=true`、`sandbox=true`、`authentication=simulated-persona-session`、`version=3.x.x`、预期模式。默认 `--expected-mode rules`；实例明确配置模型时用 `--expected-mode llm`。只核对声明，不发起模型调用，也不是模型准确率或降级链路验收。
- 系统 TLS 信任链和主机名验证始终开启；不跟随任何重定向，不使用环境代理、CookieJar、netrc 或认证头。证书失败保持失败，禁止用 `-k` 或关闭验证让报告变绿。

默认每个目标最多 96 次请求、每资源 4 MiB、总正文 24 MiB、单次 10 秒、总计 120 秒；health 上限 64 KiB，完整响应超过 3000 ms 标记失败。可在明确测量方案下调整 `--slow-ms` 等预算；这是单次探测阈值，不能据此宣称长期稳定。双目标各自独立预算，最多合计 240 秒。DNS 等待、连接、头部/正文慢滴均受截止时间约束；不解压响应，防止压缩放大。

不允许 userinfo、query、路径穿越、百分号编码、反斜杠或控制字符；资源请求仅限固定页面、health 与 `/assets/` 明确静态类型。禁止其它 API、任意文件路径；第三方资源只记“未测”，不访问、不记录其地址。数据内嵌资源不发请求。HTML base、媒体、复杂/转义 CSS 等不能完整静态解析时标记未测，必须用浏览器补验；此工具不是完整浏览器或 JavaScript 动态资源分析器。

`--output` 新建目录，写 `readiness.json` 与 `readiness.md`。目录已存在就退出，不先发请求，也不覆盖、补写或清理旧文件；写入中断留下的部分报告也保留，重新运行须换新目录。报告只含允许路径、状态、大小、耗时及固定判词，不含正文、Set-Cookie、任意错误文本、环境变量。

退出码：0＝已执行项无失败（仍可能有未测）；1＝存在失败；2＝输入/输出错误。`pass / fail / untested` 分别显示为“已通过 / 失败 / 未测”。缺少源站探测、真人手机或业务操作时必须保持未测。

## 控制台只读诊断

以下命令在**现有实例真实项目目录**执行；示例 `/opt/tropos` 仅为路径约定，先在云控制台确认。不要输出 `.env.production`、完整 `docker inspect`、完整 Compose 配置、容器环境或带敏感信息的原始访问日志。

```bash
cd /opt/tropos
python3 --version
docker --version
docker compose version
cd deploy
docker compose --env-file .env.production config --quiet
docker compose --env-file .env.production ps
app_id=$(docker compose --env-file .env.production ps -q tropos)
docker inspect --format 'project={{index .Config.Labels "com.docker.compose.project"}} image={{.Image}} readonly={{.HostConfig.ReadonlyRootfs}} network={{.HostConfig.NetworkMode}} health={{if .State.Health}}{{.State.Health.Status}}{{else}}none{{end}}' "$app_id"
docker inspect --format '{{range .Mounts}}{{if eq .Destination "/data"}}data_mount_rw={{.RW}}{{end}}{{end}} tmpfs={{json .HostConfig.Tmpfs}}' "$app_id"
```

期望应用 `readonly=true`、`network=host`、health 为 healthy，`/data` 挂载可写且 `/tmp` 为 tmpfs。以上只看状态，不试写数据库。源站权限和 SQLite 只读完整性检查不列出任何账户或交易：

```bash
docker compose --env-file .env.production exec -T tropos python - <<'PY'
import os, sqlite3
print('uid=', os.getuid(), 'data_writable=', os.access('/data', os.W_OK))
with sqlite3.connect('file:/data/tropos.sqlite3?mode=ro', uri=True) as db:
    print('quick_check_ok=', db.execute('PRAGMA quick_check').fetchone()[0] == 'ok')
PY
```

期望 UID 10001、目录可写、quick_check_ok=True。`os.access` 不代替真实写入/持久化验收；这两项需独立维护窗口验收，不能通过只读检查伪造。

网络诊断只输出 HTTP 状态/耗时，不打印响应头或 health 正文，不使用 `curl -I`（应用 health 只接受 GET）：

```bash
curl --noproxy '*' --silent --show-error --max-time 10 --output /dev/null \
  --write-out 'origin code=%{http_code} connect=%{time_connect}s ttfb=%{time_starttransfer}s total=%{time_total}s\n' \
  http://127.0.0.1:8765/api/health
curl --noproxy '*' --silent --show-error --max-time 10 --output /dev/null \
  --write-out 'public code=%{http_code} tls=%{time_appconnect}s ttfb=%{time_starttransfer}s total=%{time_total}s\n' \
  https://demo.troposagent.com/api/health
curl --noproxy '*' --silent --show-error --max-time 10 --output /dev/null \
  --write-out 'public study=%{http_code} total=%{time_total}s\n' \
  https://demo.troposagent.com/study.html
```

不加 `--location`。证书错误时检查控制台系统时间、实例证书链/续期状态和客户端系统信任库，保留原失败记录；不要粘贴任何凭据。Caddy 可在不 reload 的情况下验证已挂载配置：

```bash
docker compose --env-file .env.production exec -T caddy \
  caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
```

这不是模拟构建或成功上线的证据。本轮未在服务器执行此命令。Caddy 目前沿用原配置将 Host/Origin 映射为回环地址，以兼容后端白名单；不能把源站的 Origin 校验直接当成公网原始 Origin 已验证。不要改为通配 Host/Origin，不要开放 8765，也不要为了“连通”绑定 `0.0.0.0`。

排查分层：源站 health 失败先查应用 health/目录权限；源站成功而公网失败查 Caddy、TLS 与云防火墙现有规则；服务器公网成功而真人手机失败，继续测运营商、DNS、TLS 建连和韩国跨境链路。控制台上的公网 GET 不能代表大陆手机链路。

## 从根源码准备安全构建上下文

另一 worker 负责 `scripts/package_v3.py` 的根源码 ZIP；ZIP 不代表镜像已构建或已发布。通过云平台现有授权上传入口接收该包，先在新候选目录解压并核对清单，保留现有实例代码、生产配置和数据。不要直接上传整个开发目录，也不要把旧 `releases/` 的历史归档当作本次已核验包。

在**解压后的根目录**运行以下本地文件准备命令。它会新建隔离目录，只复制白名单；存在旧目录时直接停止，避免混入旧版本。不读 `.local`、环境文件或封存用例。

```bash
python3 - <<'PY'
from pathlib import Path
import shutil
from scripts.v3_readiness import context_manifest
root = Path.cwd()
files = context_manifest(root)  # 缺必需文件或任何源目录 symlink 即拒绝
stage = root / 'deploy/build-context'
stage.mkdir(mode=0o700, exist_ok=False)
for relative in files:
    target = stage / relative
    target.parent.mkdir(parents=True, exist_ok=True)
    shutil.copyfile(root / relative, target)
shutil.copyfile(root / 'deploy/build-context.dockerignore', stage / '.dockerignore')
print('staged_files=', len(files) + 1)
PY
```

包括 `Dockerfile`、`VERSION`、三页 HTML（**不能漏 study.html**）、`backend/*.py`、`backend/fixtures.json`、`backend/life_scenarios.json`、受限前端资源和字体/许可，以及 `reports/evaluation.json`、`reports/intent-rules.json`。这些都是运行内容；不修改/重跑源码模型评测。根源码中的额外报告、测试、环境文件、账本、备份、密钥、上传 ZIP 不进入构建目录。

只读检查该候选源码及已准备目录：

```bash
python3 - <<'PY'
from pathlib import Path
from scripts.v3_readiness import deployment_checks
checks = deployment_checks(Path.cwd())
for row in checks:
    print(row['status'], row['check'], row['detail'])
raise SystemExit(any(row['status'] == 'fail' for row in checks))
PY
```

`staged_context` 必须已通过；`docker_runtime` 仍是未测。模板检查是针对本仓库固定声明的保守核对，不是通用 YAML/Caddy 语义解析器，不能替代服务器上的 `compose config --quiet`、Caddy validate 和真实构建。Docker 的上下文与忽略规则依据[官方构建上下文文档](https://docs.docker.com/build/concepts/context/)；隔离目录内的 `.dockerignore` 默认拒绝，白名单包含必要父目录，不能复制根目录旧忽略文件替代。

构建前再核对隔离目录中只有该清单，无 symlink、未知文件或缺件。若上次准备中断，保留旧目录作证据，换候选目录重新准备，不对旧目录补拷混合版本。

## 现有实例更新与回退顺序

以下属于维护操作，会改变容器/备份文件，**不属于上面的只读诊断**；本轮只提供操作方案，没有替用户执行。使用既有控制台与实例，不依赖新增 SSH 凭据。

1. 先跑只读诊断和新目录报告，记下旧应用镜像 ID、Caddy 镜像 ID、Compose project 名、当前代码与配置路径。保存旧镜像，维护期间不 `prune`、不删卷、不覆盖生产 `.env.production`。备份配置只保存在权限受限的实例本地目录，不打印/上传。
2. 将根源码 ZIP 解压到新候选目录，按上一节生成上下文。在候选源码根目录直接执行下述 `docker build`；构建可在旧应用仍运行时完成。Compose 的生产环境文件仍在旧实例，候选目录不复制或读取它。候选目录不复制生产账本或密钥，不 `up` 第二套服务，不开放测试端口。运行 `docker build --tag tropos-candidate:v3-<本次唯一编号> deploy/build-context`，将尖括号占位符替换为本次唯一编号，保留该镜像用于核对。尚未停服务前就应完成构建，缺件/失败不得继续。
3. 在维护窗口停止真实试用，停旧 `tropos`（Caddy 可留作故障页，不向用户宣称可用）。确认没有其它进程使用此 SQLite；完整保留旧数据目录，含存在的 `-wal/-shm/-journal`。备份新建到唯一、非公网目录，不能在线只拷一个主库。
4. 使用 Python SQLite backup 从停止后的旧库生成独立备份并只读 `quick_check`。下面从**旧实例根目录**运行；它不输出表、用户或交易，已有备份目录时拒绝：

   ```bash
   python3 - <<'PY'
   from pathlib import Path
   from datetime import datetime, timezone
   import os, sqlite3
   os.umask(0o077)
   out = Path('deploy/backups') / datetime.now(timezone.utc).strftime('pre-v3-%Y%m%dT%H%M%SZ')
   out.mkdir(parents=True, exist_ok=False, mode=0o700)
   source = Path('deploy/data/tropos.sqlite3').resolve()
   with sqlite3.connect(source.as_uri() + '?mode=ro', uri=True) as src:
       with sqlite3.connect(out / 'tropos.sqlite3') as dst:
           src.backup(dst)
   target = (out / 'tropos.sqlite3').resolve()
   with sqlite3.connect(target.as_uri() + '?mode=ro', uri=True) as db:
       assert db.execute('PRAGMA quick_check').fetchone()[0] == 'ok'
   print('backup_verified=', True)
   PY
   ```

5. 保留旧源码/部署配置副本，然后将候选代码安装到旧项目路径，保持原 Compose project 名、`deploy/data` 和 Caddy 持久卷。**不要整目录覆盖旧根目录或删除现有数据**；也不要从候选目录直接 `up` 导致绑定到空的 `candidate/deploy/data`。将候选上下文放入旧项目 `deploy/build-context` 的新位置，旧上下文改名留存，不合并。恢复/核对生产配置权限及原域名；若目录 UID 不对，仅对确认的 `deploy/data` 修正 UID/GID 10001，不能对整个项目或 Docker 卷递归改权。
6. 在旧项目 `deploy/` 中，先执行 `docker compose --env-file .env.production config --quiet`，再用原 project 名执行 `docker compose --env-file .env.production -p <原project名> up -d --build tropos`；成功后再按需要更新 Caddy。Caddy 镜像/证书卷沿用现有实例，不顺手拉取/更换代理版本。原 project 名不同于目录名时必须显式 `-p`，避免创建第二套服务/证书卷。确认 healthy 后执行 Caddy validate，再 `up -d --no-build caddy` 加载本轮配置（配置没变则无需重建代理）。
7. 跑新目录的公网+源站只读报告，三页、全部本地资源、字体、版本和模式均须符合预期。另由控制台负责人验证真实容器 SQLite 权限与重启持久化；只读探测不会冒充完成这一步。最后安排下方真人手机验收，未测格不能填通过。

回退时先停止新版应用，保留新版数据库与所有 sidecar、应用镜像和失败报告。优先在兼容性确认后只回退应用镜像/代码，保留数据；若新版已迁移库结构，不能假设旧代码可直接读取。

需要回退数据库时，须由负责人明确同意恢复至备份时点（会失去此后的合成操作），先把整个当前 `deploy/data` **改名保留**，新建空 `deploy/data`，只放入已核验的独立备份并设置 UID/GID 10001 及最小所需权限。不要把旧 `-wal/-shm` 混到恢复库，不覆盖/删除故障库。恢复旧 Compose/Caddy 配置，以保存的旧镜像 ID 运行，禁止 `--build` 意外重建成新版。

可在实例本地将旧镜像 ID 标记为唯一回退 tag，创建唯一且保留的 Compose override，例如 `services: {tropos: {image: tropos-rollback:<编号>}}`；使用 `-f docker-compose.yml -f <回退override.yml> -p <原project名> up -d --no-build --pull never tropos`。启动后重跑源站/公网只读记录并核对旧版预期。v3 检查器专门要求版本 3；若回退旧版为 2.x，版本失败应如实保留，不能篡改报告将旧版写成 v3 已验收。所有恢复目录、tag、override 使用唯一编号，保留本次原始材料供复盘。

## 真人手机验收矩阵

所有格初始均为**未测**。使用真实手机，关闭 VPN/代理；Wi-Fi 与蜂窝分开，至少不同两个时段各 3 次，首次冷加载与后续刷新分开。电脑、设备模拟、云服务器 curl 和 AI 自动点击不能填进真人手机格。

| 设备/浏览器 | 无 VPN Wi-Fi | 无 VPN 蜂窝 | 记录要求 |
|---|---|---|---|
| iPhone / Safari | 未测 | 未测 | 系统/浏览器版本、粗粒度地区与运营商、时段、首次可见时间 |
| Android / Chrome | 未测 | 未测 | 同上；记录首次加载/刷新、断网恢复是否重复提交 |
| 实际使用的微信内置浏览器（若需要） | 未测 | 未测 | 单列内置浏览器，不合并到 Safari/Chrome |

每格检查：主页→工作台→`study.html` 均可进入；字体/图标完整，中文布局无横向溢出；窄屏按钮、键盘、底部安全区、滚动和错误提示可见。记录每次成功/失败与耗时，不删失败样本，不只选截图最好的一次。若试用页仍未发布或有资源缺件，立即停止招募真实试用。

`study.html` 是人工记录入口，不是自动验收。参与者本人主动同意，只使用合成账户/账本；试用记录在本人设备手动下载，不能填姓名、账号、手机号等真实资料。内部验收选 internal_acceptance，设备模拟/AI 操作不得标记为 real_participant。检查器只 GET 页面及静态文件，不填写表单、不开始任务、不下载或收集试用记录。实际会话、转账/取消等业务验收由负责人安排在明确的合成数据窗口，与本次只读报告分开。

韩国跨境网络仍待真人测量。手机访问慢可能发生在 DNS、TLS、路由/丢包或源站阶段，前端减包和本地字体只能改善其中部分环节，不能承诺纯前端修复解决。若现有合规大陆环境可用，可作为后续对照测试候选；先核实接入条件、数据边界和实际线路，不在此承诺价格、备案或法律结论，也不迁移现有站点或更改 DNS。
