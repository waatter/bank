# TROPOS 3.1：赛题对照、三分钟演示与评委问答

> 一句话：**你说一句话，TROPOS 拆成几步；只读的直接查，动钱动卡的每一步等你点头，执行前再核一遍。**

赛题是“AI 代人操作银行（安全 + 体验）”。3.1 把重点从“会聊天的规划助手”推进到“能办成一串事、而且骗不动的代理”。

---

## 一、赛题要求逐条对照

| 赛题要求 | TROPOS 的做法 | 在哪里看 | 证据 |
|---|---|---|---|
| **意图识别** | 单一意图沿用 v3 链路：模型理解后与规则逐字段比对，不一致则澄清。复合请求逐句识别：可选用大模型改写口语，但每步必须引用原话片段，然后由规则映射到工具。 | 对话框 | `tests/test_model.py`、`tests/test_agent_ops.py::ModelDecompositionTest`、`reports/intent-rules.md` |
| **任务规划** | 一句话变成有序任务单，最多 8 步，每步对应一个已注册工具。资金步骤按整单累计核验余额、现金底线和 30 天路径。“剩下的”按扣除前面步骤后的安全上限计算。 | 对话中的“任务单”卡片 | `backend/agent_ops.py::plan`、`test_compound_request_becomes_ordered_tool_steps` |
| **真实工具调用** | 共 28 个工具，覆盖转账、账单、订阅、卡片（冻结/解冻/挂失/调额）、理财（目录/申购/赎回）、亲情付（查看/批准/拒绝/暂停/恢复/调额/请家人代付）、小荷包（查看/新建/存入/取回）、预算与记账（查看/设定/记一笔/月度分析）。全部落到服务端 SQLite 复式账本，产生交易号和回执。 | 任务单执行后的回执章；账本页 | `test_confirm_executes_in_order_with_receipts_and_is_idempotent` |
| **权限分级** | **L0 只读**：直接执行。**L1 可逆**：需勾选。**L2 资金与合约**：需勾选，执行前逐项重新核验。**L3 不可逆**：需勾选并输入卡号后四位。 | 任务单的等级徽标；卡与理财页 | `test_report_lost_requires_last_four_digits`、红队用例 `api-wrong-phrase` |
| **幻觉防护** | 模型只负责改写口语。改写结果中的金额、尾号、收款人、“剩下的”、动作动词和否定词，都必须能在原话片段里找到，否则整单降级为规则拆分。收款人必须唯一对应已登记账户。金额必须精确到分。产品风险等级由服务端判定。 | 轨迹中的 METIS 说明 | `grounded_steps`、`test_ungrounded_model_output_falls_back_to_rules`、`test_dropped_negation_is_rejected` |
| **提示词注入防御** | 整句先过注入与历史引用闸，一处可疑则整单不生成任何可执行步骤。账单备注、商户名、转述内容一律视为数据。模型没有执行或确认能力。 | 安全 → 攻防演练 | `reports/redteam.md`：对话层 51/51，接口层 11/11，正常对照 14/14 |
| **失败处理** | 执行时按顺序逐步重新核验，任一步不通过即停止，后续步骤标记“已暂停”，已完成的步骤保留回执。凭证过期或账户版本变化时整单失效。重复提交只返回原结果。转账超时可凭原凭证查询，避免重复支付。 | 任务单的执行结果 | `test_failure_pauses_later_steps_and_keeps_earlier_receipts`、`test_stale_and_wrong_token_are_rejected` |
| **交易结果可验证** | 每笔资金步骤都有交易号、回执号和复式分录；卡片操作和订阅取消都有回执。日记页记录每次判断、拦截和授权。 | 回执章、账本、日记 | `api-replay` 用例（重复确认余额不变） |

## 四、评委可能追问

**问：任务单是大模型规划的吗？会不会胡编？**
可选用大模型拆分。但模型只做一件事：把口语改写成规范子请求，并逐字引用原话片段。以下内容都必须能在引用片段里找到：金额、尾号、收款人、“剩下的”、动作动词、否定词。任何一项找不到就整单降级到规则拆分，并在界面上标明“已降级”。分类、取数和核验全部由确定性规则完成。

**问：为什么不让模型直接调用工具？**
钱和卡的操作需要可复现、可审计。模型能做的只是起草：可执行的参数、额度和风险判断都由服务端规则产出；执行前还要用户勾选，L3 还要口令。所以模型被注入了，最坏结果也只是一张会被拦下或等你拒绝的草案。

**问：62/62 是不是太完美了？**
这是开发者编写的回归集，不是留出集，也不是安全认证，报告里写明了。它的价值在于每次改代码都会重跑，保证已知攻击不会回归。我们同时列出 14 条正常对照，证明安全不是靠“什么都拦”换来的。可以在评委面前用自定义输入框现场测试。

**问：多步执行一半失败怎么办？**
按顺序执行，第一处失败即停止，后面的步骤标记“已暂停”，前面已完成的步骤保留回执（不做静默回滚，避免产生“看似没发生”的资金状态）。整单可以安全地重复提交，只会返回原结果。

**问：“剩下的”到底是多少？**
取以下几项中的最小值：扣除本单前面步骤后的余额减去现金底线；30 天现金路径上的最低余量；本轮储蓄类建议限额（收入不稳定为 ¥1,000，稳定为 ¥2,000，整单累计）。任务单会写明计算依据。

**问：真实银行能接吗？**
工具层是一个注册表，每个工具有输入、权限等级、核验和回执，替换成银行开放接口时，规划与授权层不需要改。目前全部是合成数据，不连接真实银行。

**问：和普通的智能客服有什么区别？**
智能客服回答问题；TROPOS 办成一串事，并且能证明每一步为什么能做、为什么不能做。不同画像看到的界面、语气和额度不同（三扇窗），但安全规则对所有人一致。

## 五、复现

```sh
python3 -m unittest discover -s tests -p 'test_*.py'   # 含任务单、红队回归、HTTP 往返
node --test tests/*.cjs                                 # 前端与客户端
python3 -m eval.redteam                                 # 重新生成 reports/redteam.md
python3 -m eval.redteam --live-model                    # 需要模型密钥，另存 redteam-live 报告
python3 -m backend.server --port 8765 --db .local/tropos.sqlite3
# 打开 http://127.0.0.1:8765/demo.html?director=1
```

## 六、局限

- 卡片、理财产品、收益和风险等级均为合成演示数据，不构成投资建议；正式申购前应完成风险测评。
- 任务单的规则拆分依赖标点和连接词，口语化程度很高的句子会改为澄清。接入模型后改善，但仍以“宁可澄清，不可猜测”为原则。
- 前面步骤取消订阅所减少的未来扣费，暂不计入后面步骤的可用额度（偏保守）。
- 红队与对照样例由开发者编写，用于回归，不代表对未知攻击的拦截率。
