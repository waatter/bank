建议由人类研究负责人自愿招募 **5–8 位成年人**，尽量覆盖日常使用手机银行较少与较多的人，包含电脑和实际手机使用者。无需记录职业、年龄、性别或银行身份。每人约 30–40 分钟；各任务最多约 4 分钟可作为主持提示，超时由参与者选择继续或停止，页面不自动结束或判失败。不要将同一人重开多场当成新增人数。

下列邀请文案仅供负责人复制。**本包不会发送邀请、主动联系任何人或创建提醒。** 招募联系信息与匿名导出分开保管，不建立姓名—编号对照表；若协调日程必须保留联系方式，用独立渠道，不能同储在导出文件、汇总或本目录里。

> 想邀请你自愿体验一个银行助手演示原型，约 30–40 分钟。所有账户与金额均为模拟，不需要登录真实银行，也不需要提供姓名、手机号、账号或真实聊天。我们会记录一个匿名编号、任务操作耗时、是否完成、求助情况、理解核对和你的自愿反馈，用于发现哪里难懂。你可以随时跳过或停止，不影响任何权益。记录只保存在你当前设备，是否将匿名文件交给主持人由你决定。如果愿意，我们再约一个方便的时间；不参加也完全没关系。

## 3. 隐私与本人同意

主持人先读：“我们在测试产品表达。你不需要证明自己会用银行。请只使用演示账户；不要输入真实姓名、手机号、银行卡号、地址、聊天或真实交易。可以随时停止、跳过问题、拒绝提供反馈或拒绝交文件。”

请参与者本人阅读页面说明，选择标签、匿名编号、设备与网络，再**手动勾选**同意。主持人不能代勾；不使用预勾、自动化填勾或历史同意。拒绝同意则不建立场次，不记录拒绝者身份。研究同意与每一笔演示业务确认是独立决定，不能互相代替。

真人选择 `real_participant`；内部演练选 `internal_acceptance`；教学样例选 `example`。自动化测试只允许内部验收来源 `automated_test`；浏览器记录的操作来源为 `human_manual`。页面拒绝脚本合成的普通点击与勾选事件，但浏览器工具也可能产生受信事件，**事件标记不是“真人证明”**。不得把 AI 操作改标为真人，不得因为 JSON 校验通过就声称身份已验证。

页面不写本地存储或服务器。刷新、关闭或重开会清空当前内存。结束任务后结果锁定；可多次下载，文件名含匿名编号、场次 UUID 和导出序号；下载只表示发起保存，需本人检查设备文件。重开时明确提示原导出仍在设备上，新场次需重新同意；提示本身也只保留在当前页面。中途导出保留计时中状态，尚未点击结束提交的表单文字/次数不会写入文件，不被当成已采集结果。

参与者可以不交文件或自行删除。建议负责人只在本人自愿提供后接收匿名导出，放在受控本地目录，分析完成后按事先约定期限（建议 30 天）删除原文件；不要上传公共仓库或在线分析服务。仅保存必要的匿名问题摘要。文本输入会拦截明显邮箱、网址和连续长数字，但不能识别全部姓名或地址；提交前仍须人工检查。没有屏幕录制、截图或原始聊天采集授权，本包也不提供这些功能。

## 4. 主持脚本

1. **准备（约 5 分钟）**：确认应用规则模式/合成库、静态页和本地字体可访问。准备两个模拟账户：晓舟用于工资与订阅，知远用于同名转账；确保任务 6 有一项未取消的订阅。负责人自己先用 `internal_acceptance` 演练，演练文件不得混入真人目录。任务之间如果数据条件不满足，可换一个干净的合成库或用产品已有重置方式，绝不修改真人原始结果。
2. **说明与同意（约 3 分钟）**：按上一节读隐私说明。由参与者选择 `P001` 一类随机顺序编号；不要同储真实姓名。参与者本人操作同意框。核对设备及网络自报；不清楚就选 unknown。
3. **逐项操作（约 20–25 分钟）**：只读下节“给参与者的话”，不要先展示参考答案。参与者或主持人手动点“开始任务”，参与者在工作台操作，主持人观察。原则上不提示正确路径；参与者求助时可帮助，但每次给出具体操作提示计 1 次。重复同一条提示也计次；仅重复任务原话不计帮助。只记录实际观察，不替参与者点击确认。
4. **结束每项**：完成、主动停止或到约定时间后，询问理解核对题，记匿名回答摘要，再由主持人核对；不先讲答案。将“是否完成”按可观察标准主动选是/否。帮助与误解次数留空表示未采集；已全程观察且确实没有才填 0。一次独立错误主张计 1 次，同一主张的重复表达不重复计，纠正后另起的错误主张才另计。语意不清不能擅判正确，可留未采集。主观反馈自愿。核对后点击“结束并锁定”；计时包含帮助、切页与理解问答，不扣除这些时间。
5. **意外情况**：页面故障、网络中断、任务条件缺失，先让参与者决定停止或继续。已开始但未完成可结束并选否，在反馈中记非身份化原因；整项跳过则保留未开始。若刷新造成记录丢失，承认未采集，不凭记忆补造耗时。操作系统休眠或校时可能影响计时，保留原值并说明，不把差值当网络延迟。
6. **收尾（约 3 分钟）**：询问“哪里最不确定？哪条说明你会换一种说法？”参与者下载 JSON 并检查文件；本人决定是否自愿交给主持人。不要替用户确认文件已经保存成功。要修正原结果，先保留原导出，再另开场次，使用同一匿名编号，在新场反馈注明“重测任务X”，不抹掉原结果或偷偷重选成功。

## 5. 六任务规范、成功标准与理解题

共同规则：以下金额、人物都是产品已有的合成情景。任务完成与理解正确分开记录；完成并不自动代表理解正确。界面找不到按钮、方案超时、错误提示或参与者主动拒绝，都按实际情况记录，不预填结论。只有参与者本人主动授权时才确认合成业务。

| ID | 给参与者的话 / 合成前提 | 可观察完成标准 | 理解核对题 | 主持人参考要点（先不读给参与者） |
| --- | --- | --- | --- | --- |
| `profile_correction` | 在演示账户检查“我的情况”。原先准备长期存的钱，改为三个月后要用；将用钱期限改为一年内，现金底线由 ¥8,000 改为 ¥10,000，找到更新后的安排。原数据不同则先备好此合成条件。 | 找到编辑入口，主动更正并保存期限/底线，能定位更新的安排；不要求选择更高风险。 | 页面风格、风险意愿和现金承受能力分别由什么决定？改风格会改变意愿吗？ | 风格是呈现偏好；意愿来自本人风险回答；承受能力受账本与底线等约束；风格不替代风险回答，也不新增交易授权。 |
| `expected_vs_received` | 晓舟账户：找到预计工资，先模拟工资延期，观察今天余额与未来安排；再按合成情景登记到账。 | 能操作延期与到账，并分别定位今日余额、未来预测的变化；不把预计当作已到账。 | 预计工资可当作今天已到账的钱吗？延期与到账各改变什么？ | 预计只属于未来假设；延期改变未来日期/缺口，未到账不增加当前余额；登记实际到账才改变当前合成账本。 |
| `transfer_correction` | 知远账户且现金允许：说“给王磊转100元”，在同名人中选择同事，再说“改成200元”，核对后按本人意愿单独确认。 | 主动辨明收款人、更正为200，观察旧草案撤销，新草案单独确认，找到一次对应回执。 | 哪位王磊如何确定？旧100元方案能否执行？改金额是否等于付款？ | 必须澄清对象；更正撤销旧草案；更正只准备新方案，须本人另行确认；不能重复付100和200。 |
| `cancellation_impact` | 晓舟工资延期：查看会员续费，选择一项比较取消影响，先不确认。 | 找到少支出金额、最低点变化与仍存在的缺口，保持未执行。 | 取消会立即退款或增加今天余额吗？是否必然消除缺口？ | 少一次未来续费不等于退款；今日余额不因此增加；缺口可能仍在，应读实际合成结果。 |
| `cancellation_confirmation` | 为一项合成订阅准备取消方案，阅读单项卡，愿意后单独确认一次并查看原回执。 | 核对正确对象及影响，执行单项确认，找到该事项回执；不批量取消。 | 准备方案、输入“确认”、点击单项确认各做了什么？会取消全部订阅吗？ | 准备与文字确认不自动记账；单项确认才执行指定方案；不意味着批量授权或退款。 |
| `timeout_recovery` | 使用另一项尚未取消的合成订阅，启用取消超时演示；确认后结果未知时查询原方案，再刷新/恢复办理记录。 | 找到同一事项的原回执，恢复后能辨明最终状态，不新建重复请求。 | 超时一定是失败吗？怎么避免重复提交？ | 超时是结果暂不明，应按原方案/请求查询或恢复；最终状态以原回执为准；不要另发第二笔。 |

每任务四个概念并列记录：操作完成 `completed`、求助次数 `help_count`、独立错误主张次数 `misunderstanding_count`、整题理解核对 `comprehension_correct`。主观反馈不参与自动判分。帮助后完成依然记录完成，同时保留帮助次数；不要为了提高“独立完成”把帮助写成零。

预先约定的试用成功标准：准备包的工程成功是流程、隐私边界和校验测试通过；**产品试用成功不能由工程测试替代**。正式这一轮建议至少 5 个不同匿名编号、每项至少 5 个已结束观察；每项至少 80% 操作完成，并单列有帮助的完成数与理解核对分母。误把预计当到账、取消当退款、草案当已执行或超时当必然失败，任一已观察到的关键误解都列为下一轮必须处理的问题；观察到重复记账则暂停该任务并修复。分母不足或理解未采集时，结论写“材料不足”，不能判成功。5–8 人的结果只用于可用性问题发现，不估计总体可靠率或真实资金安全性；CLI 不自动签发产品通过结论。

## 6. 导出 schema 与原始数据字典

导出格式固定为 **`TROPOS-USER-TRIAL-1`**，UTF-8 JSON；一个文件对应一场的一个快照，不是参与者清单。文件名：`tropos-trial-P001-<session UUID>-<export_index>.json`。以下为结构定义，**不是样本结果**，不会生成或预装任何真人记录。

| 字段 | 类型 / 取值 | 含义与缺失规则 |
| --- | --- | --- |
| `schema` | 字符串固定值 | `TROPOS-USER-TRIAL-1` |
| `session_id` | 规范小写 UUID | 每次建场新生成，不绑定真实身份 |
| `participant_id` | `P` + 3–6 位 ASCII 数字 | 本人使用的匿名编号；不可同储真实姓名或编号映射 |
| `record_kind` | `real_participant` / `internal_acceptance` / `example` | 主动选择；内部/示例不进入真人结果 |
| `interaction_source` | `human_manual` / `automated_test` | 页面仅人工；自动化仅用于内部测试，禁止真人标签 |
| `consent.accepted` | 必须 `true` | 本人主动同意；未同意不能建场或导出 |
| `consent.method` | `participant_manual_checkbox` / `internal_test_only` | 后者仅用于自动化内部测试；不代表真人同意 |
| `consent.at` | UTC ISO 8601，末尾 `Z` | 同意后建场时刻；不早于本次主动同意操作 |
| `environment.device` | `desktop` / `real-phone` / `emulation` | 自报；设备模拟无论标签为何都排除真人结果 |
| `environment.network` | `Wi-Fi` / `cellular` / `unknown` | 自报；unknown 保留未知，不当成 Wi-Fi |
| `environment.vpn` | `on` / `off` / `unknown` | 单独自报，不把 VPN 当网络传输方式 |
| `environment.self_reported` | 必须 `true` | 不伪称技术检测或网络验证 |
| `created_at` / `exported_at` | UTC ISO，末尾 `Z` | 本场建立、该次导出时刻 |
| `export_index` | 正整数 | 本场第几次发起下载；不保证设备保存成功 |
| `tasks` | 固定六项数组，按上表 ID 顺序 | 未开始也保留槽位；不删除失败、跳过或未完成任务 |
| `tasks[].id` | 上表六个 ID | 不接受未知/重复任务 |
| `tasks[].status` | `not_started` / `in_progress` / `ended` | 只允许开始后结束，一次仅一项计时；结束结果锁定 |
| `tasks[].started_at` / `ended_at` | UTC ISO 或 `null` | 未开始均为null；计时中无结束时刻；必须按场次顺序 |
| `tasks[].duration` | 非负有限数值，秒，或 `null` | 原始单调计时差 `(performance.now结束−开始)/1000`，不四舍五入，不扣求助/切页/问答；未结束为null，不凭时间戳插补 |
| `tasks[].completed` | `true` / `false` / `null` | 人工主动判断；未结束null；false含未完成/主动停止，未开始不自动失败 |
| `tasks[].help_count` | 非负安全整数或 `null` | 实际提示次数；留空null，确已观察无帮助才填0 |
| `tasks[].misunderstanding_count` | 非负安全整数或 `null` | 独立错误主张数；同一主张重复不重复计，未核对null |
| `tasks[].misunderstanding_notes` | 1–1000字或 `null` | 匿名误解摘要，不采真实对话全文 |
| `tasks[].comprehension_answer` | 1–1000字或 `null` | 理解题匿名回答摘要；未问/未回答null |
| `tasks[].comprehension_correct` | `true` / `false` / `null` | 主持人依原回答核对；若无回答摘要，不能判对/错 |
| `tasks[].feedback` | 1–1000字或 `null` | 自愿主观反馈；不默认“满意”或“成功” |

未开始任务除 ID/status 外均须为null；计时中快照尚无已提交结果；已结束须有起止、duration及明确完成判断，其余允许未采集。记录页结果只读，导出不暗改它；本地文件不是签名证据，CLI 无法鉴别蓄意编辑或验证真人身份。结束后发现错录，保留旧文件并重开，绝不改写原结果。不同导出快照用 `session_id` 识别同场；一次汇总每场只能选一个快照，重复输入直接报错，不能累加。

## 7. 本地校验与汇总

无输入时明确生成未开展状态，人数为0，所有任务比例为null；不会制造招募名单或演示结果：

```sh
python3 -m eval.user_trial
python3 -m eval.user_trial --output /tmp/tropos-trial-not-conducted
```

第二条同时写 `/tmp/tropos-trial-not-conducted.json` 与 `.md`。已有输出拒绝覆盖，复跑换新文件名。对自愿取得的本地导出（路径替换为实际文件，不使用示例填充）：

```sh
python3 -m eval.user_trial /path/to/export-P001.json /path/to/export-P002.json --output /tmp/tropos-trial-round1
```

`--output` 可传文件名前缀或 `.md`/`.json` 路径，始终生成两种格式；不指定则只打印 JSON。任一输入不合法就整体退出码2，不静默丢掉坏记录，不输出样本结论。拒绝无同意、未知字段（含姓名等）、非法计时/状态/类型、重复 JSON 键、重复场次快照。明显身份标识要先从源头重新采集或按上述更正规则处理，不在汇总器中静默脱敏后继续计数。

汇总 schema 为 `TROPOS-USER-TRIAL-REPORT-1`。仅 `real_participant` + `human_manual` + 非emulation场次进入真人口径；内部、示例、模拟在 `excluded_sessions` 单列原因。`n_real_participants` 按**至少结束一个任务**的匿名编号去重；至少1人才有 `results_available`，否则 `not_conducted`，不称产品通过。`n_repeat_sessions` 明示重复场次；任务完成分母是已结束场次，不是人数，不能当独立样本。

逐任务保留符合口径场次、开始/结束/计时中/未开始数、完成数与分母；完成数另分为无帮助、有帮助、帮助未采集，不能把未知帮助算作独立完成。帮助、耗时、理解错误保留原始数值列表、非缺失分母、缺失数、合计、均值与中位数；全缺失的合计/均值/中位数为null。理解正确率仅以已核对回答为分母，0分母为null。设备、网络、VPN按自报场次列出，unknown保留。理解误解摘要和自愿反馈留在原始文件供人工审阅，汇总不推测满意度，不生成未观测的用户评语。
