## 1. 手机为何可能需要 VPN

用户提供的网址是 [demo.troposagent.com/demo.html](https://demo.troposagent.com/demo.html)。本轮公共 DNS 交叉检查得到 A 记录 `43.108.82.249`，无可见 CNAME 或 AAAA；本机普通解析却返回 `198.18.2.2`，提示本机代理的 Fake-IP / DNS 接管。普通请求在 TLS 连接阶段失败，尚未取得线上页面，不能把本地源码当成线上版本，也不能断言手机必须开启 VPN 的唯一原因。

用户随后确认：实例位于**韩国**，通过**阿里云控制台**管理。APNIC 的网段登记归属不能替代用户确认的实例区域。[阿里云官方网络说明](https://www.alibabacloud.com/help/en/simple-application-server/product-overview/regions-and-network-connectivity)指出，大陆访问香港及其他境外区域可能有高延迟和丢包。韩国部署与“开启 VPN 换路线后能访问”的现象，使跨境入口链路成为首要排查方向；仍需控制台日志和关闭 VPN 的手机 Wi-Fi / 蜂窝对照定位具体环节。

若面向大陆用户稳定演示，优先使用团队已有、具备上线条件的大陆运行环境，让页面与 `/api/` 同源。阿里云区域不能直接原地更换，迁移需另行部署；先保留韩国实例，完成新环境验证后再调整 DNS。已有服务、数据库、反向代理与认证配置应先备份并核对；本轮没有购买新实例、迁移账本、修改 DNS 或发布本地代码。

| 观察 | 已确认的证据 | 本轮处理与后续 |
| --- | --- | --- |
| 旧版依赖外部字体 | 已提交版本的首页和工作台引用 jsDelivr 字体；本机检查观察到部分连接超时 | 工作区已有本地字体，本轮补齐后端白名单及正确的 SVG / WOFF2 类型，并移除 CSP 对字体 CDN 的放行 |
| 新页面资源 404 | 首页引用的 `home.css`、`home.js`、`typography.css`、标志和字体没有登记静态路由 | 已修；自动检查递归读取两页和 CSS 字体依赖，检查本地来源、200 状态和响应类型 |
| 本机与公网入口不同 | 3.0 默认回环监听，同时已有显式局域网模式及 Caddy 公网代理配置 | 本机回环限制不能作为当前公网域名不通的直接解释；按 3.0 的 Caddy / HTTPS 入口检查 |
| 静态托管缺少后端 | 工作台经 HTTP 打开后必须连接同源 `/api/health`，然后读取服务端账本 | 完整手机演示需可达的页面与同源 API；仅把 HTML 上传到静态托管不能完成银行业务 |
| 线上托管与网络链路 | 已取得用户提供的韩国实例域名，公共 DNS 一致指向阿里云网段；3.0 的部署配置位于 `deploy/` | 核对实例运行的具体版本、Caddy 状态、关闭 VPN 的 Wi-Fi / 蜂窝网络、443 连接与 `/api/health`，再按失败层处理 |

本地检查通过不代表手机运营商网络已验证。真实多人部署需要独立会话与账户隔离；现有 A/B/C 模拟登录不应被包装为生产认证。

## 2. 研究依据与取舍

不存在可据此宣称“最先进且适用于本项目所有用户”的单一画像算法。当前仅有三份合成演示账本，无法可靠训练人群聚类、校准风险概率或验证量表。采用研究支持的维度设计与可复核规则，先把输入、解释、更正和事件更新做完整。

| 原始来源 | 与本项目有关的发现或要求 | 落实方式 |
| --- | --- | --- |
| [CFA Institute：2026 Portfolio Planning](https://www.cfainstitute.org/insights/professional-learning/refresher-readings/2026/basics-of-portfolio-planning-and-construction) | 区分承受风险的意愿与能力，并考虑期限和流动性等约束 | 分开采集意愿，依据账本计算当前能力；较高收益目标不自动提高可承受档位 |
| [ESMA：2023 suitability guidelines](https://www.esma.europa.eu/sites/default/files/2023-04/ESMA35-43-3172_Guidelines_on_certain_aspects_of_the_MiFID_II_suitability_requirements.pdf) | 需要知识、经验、财务状况、损失承担能力、目标与容忍度等信息，并识别不一致 | 补知识情景、经验、期限与流动性；冲突答案先复核。此处是设计参考，不宣称完成中国市场适当性合规 |
| [Potts、Grable、Murphy，2025，Financial Planning Review](https://onlinelibrary.wiley.com/doi/10.1002/cfp2.70020) | 两期投资者调查支持使用金融领域知识与经验理解风险承担，泛化人口属性的解释较弱 | 不用职业、年龄、性别或页面字体替代承受能力；关注可更正的具体财务信息。该相关性研究不证明本项目分流有效 |
| [Cho、Bae、Kim，2026，arXiv:2603.09303](https://arxiv.org/abs/2603.09303) | 模型在风险问卷上的回答存在默认倾向与提示敏感性 | LLM 可解释、追问；档位和权限不由模型自由生成。研究测量的是模型作答，不能直接当作真人画像准确率证据 |
| [Bakshi 等，2026-10-16，arXiv:2610.23060](https://arxiv.org/abs/2610.23060) | 同一人重答风险问题的噪声可能被 AI 建议放大；脚本化的追问确认显示出缓解作用 | 加入矛盾复核，明确用户是在更正答案还是确认偏好；为后续重复测量和建议稳定性检查留下规格。该文是预印本，其实验结果不等于我们的效果 |

以上研究提供的是维度与审计方向。本项目问法、档位映射和阈值均为团队设计，未经真实用户量表验证；不能称为 CFA / ESMA 认证问卷。

## 3. 先建画像，再生成不同的工作台

入口顺序：**选择模拟账本 → 目标 → 现金与收入 → 风险与用钱期限 → 阅读偏好与读取同意 → 画像预览与确认 → 我的安排。**

画像包含六类信息：目标及期限、现金承担能力、流动性需要、损失承受意愿、损失情景中的反应、金融知识与经验。三种阅读风格独立于这些判断。数据不足时明确待完善，旧用户没有风险答案时不自动补答。

| 工作台角色 | 先处理什么 | 实际入口 |
| --- | --- | --- |
| 待完善／复核 | 缺少答案、矛盾未复核或资料待确认 | 补充画像与解释 |
| 现金修复 | 30 天最低余额已经低于本人现金底线 | 现金缺口、每日账单、续费取消影响 |
| 弹性缓冲 | 收入波动或现金缓冲偏薄 | 现金日历、固定续费、生活安排 |
| 负债减压 | 还款负担或明确的减债目标 | 到期还款清单、现金安排 |
| 近期目标 | 较近的用钱期限或目标 | 生活目标比较、分步安排 |
| 稳健积累 | 维持必要支出与缓冲后积累目标 | 现金核对、目标规划 |
| 长期规划 | 期限、流动性、知识和能力允许进一步讨论 | 长期目标与资金安排；不提供尚未实现的投资申赎 |

七种是可扩展的服务角色，不是七个从低到高的风险等级。角色会随现金事件更新，长期偏好不会被一次消费自动改写。意愿与能力约束后给出最多五档的波动承受参考，并保留原因；它不是授信评分、亏损概率或具体产品推荐。

工作台实际调整标题、优先操作、账单／目标详情和解释内容。全部银行能力继续保留，付款约束不因角色变化而放松。画像不会替代 ARGOS 的服务端金额、余额、版本、确认凭证和幂等检查。

## 4. 距离争冠最应补什么

[官方赛题](https://fintechathon.g-ican.com/)要求银行 AI 智能体理解自然语言、规划并执行银行业务，六类核心场景至少覆盖三类，鼓励完整覆盖。官网列示 10 月 28 日人工智能答疑、11 月 2 日提交截止。下面是团队取舍，不是官方评分表。

| 优先级 | 当前缺口 | 提交前可验收的结果 |
| --- | --- | --- |
| P0 | 访问和演示入口不稳定 | 手机关闭 VPN 可进入页面；页面、字体和 API 都能访问；桌面与窄屏完整走通；保留备用录屏 |
| P0 | 业务已有接口，但对话闭环不足 | “查询续费 → 明确哪项 → 比较影响 → 逐项确认取消 → 核对回执 → 重算安排”完整完成；支持至少一种多轮更正，旧草案失效 |
| P0 | 已知用例成绩不能证明陌生需求泛化 | 冻结版本，由未参与开发者准备约 40 条新任务；分别记录模型、规则与降级，统计任务完成、误执行、误拒绝、耗时和恢复情况 |
| P0 | 动态画像差异尚缺公平对照 | 同一数据、同一工具与安全网关，对比普通 LLM、静态画像、事件更新画像；记录未知事件、反事实、失败和重测稳定性；不用已知规则最优解冒充真实收益 |
| P1 | 缺少真实使用证据 | 邀请 5–8 名参与者，记录是否会纠正画像、区分预计工资与到账、理解取消影响、完成确认；报告观察而不编造效果百分比 |
| P0 | 官方接口与交付要求尚未锁定 | 10/28 答疑确认自建沙箱是否接受、指定接口、视频与材料格式、是否要求公开链接；干净环境复现最终提交包 |

不建议在初赛截止前同时铺开六场景。若上述主线已稳定，再考虑增加一条具备状态、授权、失败恢复和回执的卡片限制／解锁流程；仅新增页面不能算新增银行操作。

### 三分钟展示主线

先用问卷建立画像并解释工作台侧重 → 同一条银行需求在不同现金状况下产生不同安排 → 工资延期后更新现金角色与任务 → 指定订阅、确认取消、查回执、重算仍存在的缺口 → 准备小额转账并单独确认 → 超时后查原回执、重试不重复扣款。

故事的核心是：**知道用户现在能做什么，情况变了重新安排，确认后的每一步都有结果。** 风险问卷与界面服务于这条办理链。
