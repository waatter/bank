# TROPOS 购物连接器接口

## 当前交付

“帮我买”现在包含两条清晰分开的链路：

- **美团 Mock**：合成商品搜索、预算与现金路径检查、订单预览、逐笔确认、模拟扣款、模拟回执和履约推进。不会调用真实美团。
- **美团官方跑腿 Skill**：本人账号授权、地址簿、帮买实时配送费询价、真实订单创建、美团收银台跳转和订单状态查询。商品与配送费确认后才会提交，支付必须由用户在美团页面完成。

官方链路使用美团官方仓库 `meituan/MT-Paotui-For-Client` 的客户端 Skill。它解决的是“帮我买一束花、买一杯咖啡”等跑腿帮买，不是餐厅菜单搜索；正式外卖菜单、门店、购物车及优惠仍需另行申请美团的商业开放平台能力。

## 用户流程

1. 在“帮我买”页点击“连接美团账号”。若本机已有仍有效的官方授权则直接复用并登录 Skill；否则打开约十分钟有效的官方授权页，由本人完成授权。
2. 选择美团地址簿中的地址，描述要买的物品并设置商品最高预算。
3. 服务端用完整联系方式短暂调用官方接口，网页只收到脱敏手机号；完整手机号、Token 与完整地址不写入 TROPOS 数据库。
4. 官方接口返回配送费与时效后，TROPOS 用当前模拟账本检查预算、余额、现金底线与 30 天现金路径。
5. 用户勾选本单确认后才创建真实订单；配送费超过 ¥100 时需要第二次高额确认。
6. 订单创建后生成美团收银台链接。TROPOS 不代替用户支付，也不把真实消费伪装成模拟银行扣款。
7. 后续状态只展示美团接口明确返回的文字；取消订单暂需在美团 App 中处理。

## 安装与运行

本机默认目录：

- Skill：`%USERPROFILE%\.codex\skills\meituan-paotui`
- 授权工具：项目 `.local\meituan-runtime\package\dist\index.js`
- 授权缓存：官方授权工具自己的本机缓存；TROPOS 数据库不保存访问令牌

默认会自动寻找 Codex 自带 Node 运行时。需要在其他电脑或服务器运行时，可覆盖：

```dotenv
TROPOS_MEITUAN_SKILL_DIR=D:\path\to\meituan-paotui
TROPOS_MEITUAN_NODE_BIN=D:\path\to\node.exe
TROPOS_MEITUAN_PASSPORT_JS=D:\path\to\package\dist\index.js
```

这些变量只应在服务端配置，不能放进浏览器脚本。启动服务后，`GET /api/shopping/paotui` 会返回组件是否安装、是否已连接以及当前演示账户能否使用；不会返回 Token。

## HTTP 能力

| 接口 | 作用 |
|---|---|
| `POST /api/shopping/paotui/auth/start` | 生成约十分钟有效的官方授权入口 |
| `POST /api/shopping/paotui/auth/complete` | 本人授权后检查连接并登录 Skill |
| `POST /api/shopping/paotui/logout` | 明确确认后断开本机美团账号 |
| `GET /api/shopping/paotui/addresses` | 读取地址簿，手机号脱敏返回 |
| `POST /api/shopping/paotui/preview` | 帮买实时询价并运行资金检查 |
| `POST /api/shopping/paotui/previews/{id}/confirm` | 使用报价凭证创建真实订单 |
| `POST /api/shopping/paotui/orders/{id}/payment` | 重新取得官方收银台链接 |
| `POST /api/shopping/paotui/orders/{id}/status` | 查询订单与审核状态 |

## 安全与产品边界

1. Mock 与真实订单在页面、接口、数据库和审计记录中始终明确区分。
2. 一个本机官方美团授权只绑定一个演示账户，切换 A/B/C 不会看到另一个账户的真实订单。
3. Token 只通过子进程环境变量传给官方程序；不进 HTTP 响应、SQLite、模型上下文或审计文本。
4. 完整收件手机号仅在读取地址详情、询价和提交订单时存在于服务端内存；数据库只保存不可逆地址指纹和供应商订单引用。
5. 报价十分钟后失效；画像或账本版本变化后必须重新询价。
6. 请求超时或供应商未返回明确订单号时标记为结果未知，禁止重复提交。
7. 真实订单金额不会修改当前模拟银行账本。只有 Mock 订单才记录模拟扣款。
8. 当前服务仍只监听 `127.0.0.1`。若未来部署为多人服务，必须重新实现每位真实用户独立的 OAuth Token 加密存储、回调、撤销、密钥轮换与合规审计，不能直接复用本机单账号授权模型。
