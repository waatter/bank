### 注册登录与用户隔离

工作台右上角“注册 / 登录”支持创建持久化账户。用户名大小写不敏感，每个账户生成不可预测的 `usr_…` 用户 ID；密码使用独立随机盐值的 scrypt 慢哈希保存，不存明文。登录会话使用高熵随机令牌，数据库仅保存令牌 SHA-256 校验值，24 小时后失效，退出登录会立即撤销当前令牌。连续错误密码会触发 15 分钟限制。

账本、画像、转账方案、对话、个人模型选择/API Key 内存空间以及美团授权均以服务端用户 ID 分区。注册时选择的 A/B/C 只作为初始合成数据模板，不会复用同模板其他用户的用户 ID 或后续数据。个人 API Key 仍只存在服务进程内存，服务重启后需重新接入。

邮箱验证、找回密码与 TOTP MFA 已接入。注册会向邮箱发送 15 分钟有效的一次性验证链接；找回密码始终返回相同提示以避免枚举账户，重置成功后撤销该用户全部旧会话。MFA 兼容标准验证器 App，启用时生成 10 条只展示一次的恢复码；登录动态码不可重放，连续错误最多 5 次。TOTP 密钥不直接写入数据库，而是由服务器主密钥和用户随机版本派生。

本机未配置 SMTP 时，验证和重置邮件写入权限受限的 `.local/mail-outbox/`，不会在网页、控制台日志或 API 中返回令牌。生产环境必须在 `.env.production` 配置 `TROPOS_PUBLIC_URL`、`TROPOS_SMTP_*` 和持久化的 `TROPOS_AUTH_MASTER_KEY`；主密钥轮换会使现有 TOTP 绑定失效，必须纳入加密备份。配置示例见 [`.env.example`](../.env.example) 和 [`deploy/env.production.example`](../deploy/env.production.example)。

新增“帮我买”消费代理，提供两条明确分开的链路：美团 Mock 可完成合成商品搜索、预算检查、模拟扣款和履约演示；美团官方跑腿 Skill 可由本人授权后读取地址簿、获取帮买实时配送费、逐笔确认真实订单、跳转美团收银台并查询状态。每位已登录用户拥有独立的美团授权、地址访问和订单空间，互不读取、复用或退出对方账号。真实订单不会修改模拟银行账本，支付仍由用户在美团页面完成。该能力适用于“帮我买一束花”等跑腿帮买，不等同于餐厅菜单外卖接口，详见 [购物连接器接口](../docs/购物连接器接口.md)。

## 启动服务端版本

需要 Python 3.10 或更新版本；运行与 Python 测试仅使用标准库，无需安装第三方包。在项目目录运行：

Windows 推荐直接双击项目根目录的 `一键启动-TROPOS.cmd`。它会自动定位 Python、避免重复启动、等待服务健康后打开演示页；启动失败会显示原因，并把服务日志保存在 `.local/server.out.log` 与 `.local/server.err.log`。原入口 `scripts\start-windows.cmd` 仍然可用，并调用同一套启动逻辑。

需要从同一 Wi-Fi 的手机临时演示时，可在项目忽略目录 `.local/lan-access.json` 中配置电脑局域网地址和 `"accessMode":"open"`，再以 `--host 0.0.0.0 --lan-config .local/lan-access.json` 启动。手机无需口令；同一网络内拿到地址的设备也都能访问并修改合成数据。Windows 入站规则应只允许该后端程序、TCP 8765 和本地子网。校园网若开启客户端隔离，仍可能阻止设备互访。

```sh
./scripts/run.sh
```

打开 [银行工作台](http://127.0.0.1:8765/demo.html) 或 [概念展示页](http://127.0.0.1:8765/index.html)。也可以直接启动：

```sh
python3 -m backend.server --host 127.0.0.1 --port 8765 --db .local/tropos.sqlite3
```

服务默认只监听本机回环地址，不能作为云端共享地址使用。SQLite 账本保存在 `.local/tropos.sqlite3`，停止并重启服务后仍保留；在画像页可明确确认后重置当前模拟账户。浏览器用 `sessionStorage` 保存模拟会话凭证；会话失效后需重新选择账户。

### 模型中心：平台模型 + 用户自带模型（BYOK）

工作台“安全 → 模型中心”同时支持两种方式：管理员配置的“平台模型”由平台密钥承担 Token 费用；“我的模型”允许当前登录账户接入自己的 DeepSeek、OpenAI、Kimi 或自定义 OpenAI 兼容 API，Token 费用由用户自己的模型账户承担。未配置密钥也能运行，界面会明确显示“本地规则”；未配置的外部模型不能被误选。选择结果和个人配置按当前模拟账户隔离，不会出现在其他账户中。

可信本机演示可用 `python -m backend.server ... --model-admin` 启动，管理员可在页面临时配置平台模型；平台运行时密钥只保存在当前服务进程，重启即清除。`scripts/run_windows.py` 在纯本机模式会自动开启该能力，局域网模式不会开启。公开服务器默认禁止网页修改平台密钥，避免访客替换配置或消耗管理员额度；平台模型应在服务器的 `deploy/.env.production` 中持久配置。

个人 BYOK 配置始终只保存在服务器进程内存中，按唯一用户 ID 分区，不写入 SQLite、浏览器存储或审计日志，也不通过接口回传；用户可以测试、切换和主动移除，服务重启后自动清除。公开部署必须使用 HTTPS；若要处理真实金融资料，还需补充实名与银行卡身份核验、集中密钥托管、风控监控、审计留痕和合规审查。

如需调用模型，若项目尚无 `.env`，先复制 `.env.example` 为 `.env`，仅在本机填入对应服务。例如 DeepSeek：

```dotenv
TROPOS_DEEPSEEK_API_KEY=在本地填写你的密钥
TROPOS_DEEPSEEK_BASE_URL=https://api.deepseek.com
TROPOS_DEEPSEEK_MODEL=deepseek-flash
TROPOS_DEEPSEEK_TIMEOUT=15
```

OpenAI、Kimi 和自定义接口的完整变量见 [`.env.example`](../.env.example)。原有 `TROPOS_LLM_*` 与 `DEEPSEEK_API_KEY` 仍兼容。启动脚本只按数据读取白名单中的模型配置，不执行 `.env` 命令，不自动读取用户主目录的密钥；已有进程环境变量优先。修改配置后重启服务。`.env`、`deploy/.env.production` 和 `.local/` 不应上传。

不同服务按各自正式接口调用：OpenAI 使用 Responses API，并可调用原生 `web_search` 返回来源；DeepSeek 使用 Chat Completions 与官方 Search API；Kimi 使用 Chat Completions 与 Search Pro；自定义服务使用 OpenAI 兼容的 `/chat/completions`。普通问答可携带当前账户最近几轮只读对话，用于理解“第二个”“继续比较”等指代；它不能把历史文字变成付款授权。明确提出联网、最新信息、来源或链接时，TROPOS 会先调用当前供应商已接入的官方搜索能力，再由模型归纳并把来源链接展示在页面。未取得来源时会如实标注不可用，不会伪造搜索结果。

普通办理只发送用户主动输入的当前消息和固定系统提示；多轮只读问答只追加近期普通对话文字。当用户请求生活或财务方案且已授权读取画像时，还会发送由服务端生成的脱敏汇总，包括余额、现金底线、未来 30 天现金路径、消费分类合计和必要账单合计。原始流水备注、商户明细、收款账号、会话令牌、用户标识和 API Key 不会发送。模型可理解意图、拆解任务、联网检索并提出生活方案；金融计算、建议上限、付款授权和逐笔确认由 TROPOS 服务端决定。输出必须通过动作、字段、金额上限、服务入口、来源编号、收款人与时间条件校验；配置失效、方案越界或个人密钥在重启后清除时，安全降级为本地规则。完整能力矩阵与终端差异见 [模型 API 能力说明](../docs/模型_API_能力说明.md)。

银行助手会同时显示“当前理解服务”和每条回复的“本次已调用／本次未调用”。安全拦截、明确上下文处理等步骤可能继续使用本地规则，即使已选择外部模型；这会如实标注，而不会把规则结果伪装成模型回答。模型中心的“测试连接”会发送一句合成测试消息并可能产生少量 API 费用，只有用户明确点击后才调用。

本轮已用 `deepseek-flash` 真实 API 验证“自然语言 → 合成银行待确认转账草案”，该检查没有确认交易、没有扣款，见 [脱敏检查记录](../reports/model-smoke.json)。确认记账、超时查询和重复提交防护由另外的 HTTP 集成测试覆盖，不能合称为一次模型自动付款。

## 两种打开方式

| 打开方式 | 业务状态与保存 | 模型与执行边界 |
|---|---|---|
| 通过上述 HTTP 服务打开工作台 | SQLite 是账本和画像的依据；服务端核验、确认、记账并返回合成回执 | 可配置真实模型理解；付款必须单独确认；服务中断时停止操作，不悄悄切换到本地交易 |
| 直接打开 `demo.html`，地址以 `file://` 开头 | 浏览器内的交互样例；支持时用 localStorage 保存，数据不与 SQLite 同步 | 本地规则和模拟状态，只适合查看交互，不经过服务端授权与账本 |

字体随项目本地加载：中文使用 Noto Sans SC，英文与金额使用 Manrope；无需运行时连接字体 CDN，许可见 `assets/fonts/`。购物申请与冷静期守护目前均为前端评估和建议，即使在 HTTP 模式下也没有接入支付拦截。“陌生人陪审团”的意见由本地规则生成，没有真实用户参与。

## 已实现的行动链

| 环节 | 当前实现 |
|---|---|
| 知己 ETHOS | 四步画像建立；目标、现金底线、收入稳定性、风险与用钱声明、表达风格和服务偏好由用户确认；账本事件触发状态与角色更新 |
| 善谋 METIS | 按服务端快照确定性计算未来 30 天现金路径、必要账单、缺口和建议上限；模型可基于经授权的脱敏汇总提出生活方案，但不能改写这些金融事实或执行操作 |
| 择时 KAIROS | 追踪工资依赖和待确认任务；工资到账移除同笔预计收入、只记账一次；条件满足后仍需重新生成方案并逐笔确认 |
| 守诺 ARGOS | 明确收款人、单笔限额、已到账余额、用户现金底线、未来现金路径、工资条件、方案版本、确认凭证与有效期检查 |
| 回执与追溯 | SQLite 持久账本、以分为单位的复式分录、幂等凭证、审计记录和画像前后变化；接口结果未知时按原凭证查询 |

转账方案在生成时检查，确认执行时再检查。修改画像、工资到账或新增账单等事件会使旧方案需要重新核验。重复确认同一方案返回原回执，不重复扣款。模拟超时接口先完成事务，再返回 `UNKNOWN`，前端随后按原凭证查询，不另建一笔付款。

转账页的“找回我的方案”从服务端读取当前账户最近 50 个方案。刷新页面或服务重启后，仍能核对待确认、等待条件、检查未通过、过期、账户变化后失效、撤销和已记账状态。已记账方案只查询原回执；失效方案可填回表单重新检查。读取不改账、不自动续期或转账，确认框也会随凭证到期失效。

当前没有后台自动执行器。工资到账只把相关既有任务恢复为待确认；它不执行转账、提前还款或理财申购。未确认的意向不计作已授权现金支出，必要账单和有效订阅仍纳入预测。用户采纳预算建议也不等于账单方同意延期。

### 画像为什么要动态更新

画像分为用户确认的选择、最新财务状态、规则计算的策略侧重。首次体验需主动同意读取模拟账本；之后无需每次登录重新回答问卷。用户更正目标或底线时需确认，工资延期、工资到账、维修账单、转账和订阅取消则触发重算与来源记录。事件不会自动更改长期目标、现金底线或操作权限。

3.0 当前使用 `ETHOS-R2` 多维规则画像，七种工作台角色与风险分档独立于阅读风格；旧 `ETHOS-R1` 百分比仅为历史规则权重，不是风险概率或模型置信度。同一句“帮我打理这两万元”，会按各账户的实际目标、现金最低点、到期债务和待办给出不同建议。工资延期造成缺口时，计划明确保留缺口，建议暂停新增非必要转出，不凭空取消必要还款或降低预算。

### 三份演示账本与阅读风格

| 用户 | 关注点 | 窗景与表达 |
|---|---|---|
| 晓舟 | 灵活收入、近期刚性支出与现金缓冲 | 清晨雾蓝；宋体，先给当前结论 |
| 望舒 | 分期叠加、账单分散与负债减压 | 深夜灯火；楷体，温和、便于逐项核对 |
| 知远 | 收入稳定、目标安排与精确控制 | 正午网格；黑体，数字先行 |

窗景的山高对应每天的余额，水面对应用户现金底线。界面另有画像、账本、订阅、转账、审计日记和“先别买”购物申请。职业、年龄、性别或地域不作为资金权限依据；表达风格也不改变付款约束。

晓舟、望舒、知远是合成账本身份；不对应固定风险档位。确认画像后，“我的安排”按当前角色调整标题、优先事项和账单／目标详情，其他业务入口仍然可用。波动承受参考最多五档，收入冲击只影响当前能力与安排，长期风险声明仍保留。

合成账本固定以 2026 年 10 月 20 日为基准，未来 30 天的日期和现金预测从该日起算，不随电脑日期滚动。

## 建议演示顺序

1. 启动 HTTP 服务，选择晓舟，完成画像与读取同意；用“帮我打理这两万元”查看真实现金数字、建议依据和待办。
2. 切到知远并完成首次确认，再问相同问题，比较目标、现金余量与方案；切回晓舟。
3. 模拟“工资晚 15 天”，查看现金缺口、画像前后记录和仍在等待的任务；目标与现金底线保持用户原选择。
4. 切到现金条件允许的账户，在转账页或对话中草拟小额转账，单独确认并选择超时演示；按原凭证查询回执，再重放同一确认验证余额只变一次。
5. 模拟工资到账，查看到账只记一次、预计收入被移除、任务恢复待确认；需要执行时重新生成方案并单独确认。
6. 查看取消订阅回执、审计日记与“先别买”；说明购物守护的前端边界，再打开实际生成的规则对照报告。

## 可复跑核验与规则对照

Python 测试不调用付费模型 API，模型响应使用本地模拟服务或 mock。Node 检查需要支持内置 `fetch` 的 Node.js 18 或更新版本。

```sh
python3 -m unittest discover -s tests -p 'test_*.py' -v
node tests/profile-invariants.cjs
node tests/risk-profile.cjs
node --test tests/personal-ui.cjs
node tests/backend-client.cjs
node --test tests/client-session.cjs
node --test tests/modal-accessibility.cjs
node --test tests/life-ui.cjs
python3 -m eval.benchmark --output reports/evaluation.json
python3 -m eval.intent_benchmark
python3 -m eval.life_benchmark --output reports/life-planning.json
```

Python 检查覆盖领域账本、授权版本与有效期、工资去重、事务回滚、服务重启、用户隔离、HTTP 入口、并发幂等、模型输出白名单与评估口径。Node 检查覆盖本地业务不变量，真实 HTTP 客户端与工作台之间的数据衔接，以及会话恢复和过期处理；工作台衔接检查使用替代 DOM，不构成浏览器点击或视觉验收。

规则对照使用 **48 个预先定义的合成场景、144 次独立运行**：3 位用户 × 4 种事件 × 4 个请求上限，分别运行固定规则、静态画像和动态画像。结果见 [可读报告](../reports/evaluation.md) 与 [逐场景数据](../reports/evaluation.json)，记录输入和实际源码指纹。

所有策略共享同一个安全网关，评分以独立整数分计算核对现金路径。它验证“按最新事件重算”的工程效果；没有调用模型，不能证明自然语言理解或真实银行能力。动态策略使用已知当前数据，与该确定性任务的参考可行上限一致，不能将其达成率当作泛化结论。共同的零新增违规不归因于动态画像独有的安全优势；原本因冲击造成的现金缺口也没有因此被修复。报告不涉及真实用户、随机试验、逾期改善或因果收益。

另有 [41 条固定自然语言用例](../eval/intent_cases.json)，分别检查动作、完整金额与参数、应澄清请求和草案未执行边界。[修复前记录](../reports/intent-rules-before.md)保留实际误读，[当前规则结果](../reports/intent-rules.md)使用相同预期复跑。开发使用过这些用例，因此成绩只作为回归证据；未知表达仍需独立盲测。原有单条意图接口继续对缺少上下文的更正作澄清；3.0 工作台通过独立的持久对话接口支持明确的金额更正、关系澄清和草案撤销。未支持的日期条件、跨话题指代、批量操作和代确认仍需澄清。

规则任务检查强制不使用环境中的模型密钥。只有显式运行 `python3 -m eval.intent_benchmark --live-model` 才会读取进程环境并可能产生 API 费用；它仍只草拟，不确认付款。未运行真实模型任务集时，不生成或宣称模型成绩。该命令不自行加载项目 `.env`。
