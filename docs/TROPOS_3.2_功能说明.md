# TROPOS 3.2 功能说明

## 本轮目标

3.2 将 3.1 的现金行动能力升级为“可解释的 AI 财务体检”。它不只给结论，还同时回答四个问题：用了什么数据、按什么规则判断、有哪些信息不知道、最后由谁决定。

## 已实现

### 1. AI 财务体检

- 比较未来 30 天现金最低点与用户自行设定的现金底线。
- 区分紧急、值得复核、暂时平稳三类状态，不虚构无法验证的综合信用分或健康分。
- 汇总小额可见消费，以及标记为“低使用”或“重复”的有效订阅。
- 保留原有账单日历、逐日现金路径、订阅单项取消预览和操作回执。

### 2. 标准化解释卡

体检页固定展示：

- 数据：当前可见合成流水、登记账单、有效订阅、逐日现金节点。
- 规则：现金底线比较、小额支出范围、续费标记和流水复核阈值。
- 未知项：不完整流水、现金消费、其他账户、临时账单和预计收入的不确定性。
- 决策边界：系统负责发现、计算和解释；转账、取消续费、付款和画像变更仍由用户逐项确认。

### 3. 金融白话翻译器

新增只读接口 `/api/financial-glossary`，解释可用余额、现金底线、预计到账、自动续费、汇率、手续费、到账时间、风险提示、非保本和分期。页面可搜索，解释不包含产品推荐、收益承诺或操作链接。

### 4. 长辈友好模式

- 顶栏可一键开启，并在当前浏览器保存显示偏好。
- 放大字号、按钮和关键说明，不隐藏风险、假设或确认信息。
- 转账确认前用独立区块再次展示收款人、账号尾号、金额和执行时间。

### 5. 模型中心

- 在“安全 → 模型中心”统一展示本地规则、DeepSeek、OpenAI、Kimi 和自定义 OpenAI 兼容接口。
- 同时提供“平台模型”和“我的模型（BYOK）”：前者由管理员配置并承担费用，后者由用户接入自己的 API Key 并承担 Token 费用。
- 平台密钥通过服务器环境变量持久配置；个人密钥只存在服务器进程内存，按认证账户隔离，重启自动清除。
- 浏览器不读取、不显示也不保存完整 API Key；接口响应、SQLite 和审计日志均不包含密钥。
- 每个模拟账户独立保存自己的模型选择；一个账户切换不会改变其他账户。
- 未配置的服务保持可见但不可选择，并明确列出缺少的配置项；已选配置失效时自动回退本地规则。
- 可信本机管理员模式允许在页面中配置并立即启用模型；密钥仅保存在当前进程，重启即清除。
- 公开部署默认不开放网页修改平台密钥，由管理员通过 `.env.production` 配置；用户仍可接入、测试、切换或移除自己的内存型模型配置。
- 银行助手显示当前服务，并在每条结果上标明该条消息是否实际调用外部模型。
- “测试连接”只发送固定合成测试句，明确提示可能产生少量 API 费用后才会调用。
- 切换外部服务前再次说明数据发送边界和费用承担方，并清理当前浏览器中的旧对话指针，避免跨模型继续未解决事项。
- 普通办理中，模型仅接收当前消息并负责意图理解与任务拆解。用户请求生活或财务方案时，在已同意读取画像的前提下，模型还会接收服务端生成的脱敏汇总（余额、现金底线、30 天现金路径、消费分类与必要账单合计），但不会收到原始流水备注、商户明细、收款账号、用户标识、会话令牌或 API Key。模型不能改写服务端建议上限，也不能确认或执行金融操作。
- 银行助手支持生日安排、双十一购买方案、本月与下月支出建议等结构化方案；模型输出须通过字段、文字、金额合计和服务入口白名单校验，越过服务端预算上限时自动降级为本地安全方案。
- 普通只读问答支持最近几轮对话上下文，可以继续追问和比较；历史对话不能被当作转账、付款、取消或下单授权。
- OpenAI 通过 Responses API 使用原生 Web Search；DeepSeek 通过官方 Search API；Kimi 通过 Search Pro。检索结果先作为不可信只读证据交给模型，再把实际来源链接展示给用户；没有来源时不伪装成联网回答。
- 模型中心会展示每个服务当前已接入和仅“API 可用但页面尚未开放”的能力，避免把图片、文件、流式输出等供应商能力误报为本项目已经支持。

当前版本同时支持共享 A/B/C 演示账户和持久化用户名/密码账户。注册账户拥有唯一用户 ID、独立合成账本、独立个人模型与美团授权空间，并支持会话撤销和错误密码限制；密码以带独立盐值的 scrypt 慢哈希保存。邮箱验证与找回密码使用 15 分钟、单次消费的随机链接，密码重置撤销全部旧会话；TOTP MFA 支持防重放动态码和一次性恢复码。公开部署须使用 HTTPS 和正式 SMTP。该身份层仍不包含实名、活体或银行卡要素核验，不能被视为生产银行身份系统。

对应只读状态接口为 `GET /api/model-center`，账户选择接口为 `PUT /api/model-center/selection`。本机管理员模式提供平台运行时配置；个人配置使用 `/api/model-center/personal/providers/{provider}` 接入、测试与移除。服务端支持本机、Linux 启动脚本和 Docker 部署读取同一套平台白名单配置。

## 安全与适用范围

- 所有账户、流水和商户信息仍为合成数据。
- 财务体检和术语解释是只读能力，不产生确认令牌，也不修改账本。
- “风险提示”只代表公开规则命中，不是欺诈判定。
- 预计工资不是到账保证；依赖预计收入的安排仍须等待真实到账。
- 长辈友好模式只改变显示方式，不降低任何确认要求。
- 模型中心的服务地址、模型名和配置状态可以返回给页面，密钥本身永不进入接口响应。

## 与推文建议的对应

- 从问答升级为“理解目标—读取授权数据—计算—解释—给出下一步”的任务链。
- 覆盖生活费去向、隐性小额支出、续费、现金压力、风险提示原因和金融白话解释。
- 对关键操作坚持人工决定；系统不能代替用户确认。
- 将证据、推断和不确定性分开展示，避免把模型输出包装成确定事实。

## 后续可拓展

- 小微商户现金流体检：应收、应付、回款延迟和工资压力情景。
- 跨境汇款比较：汇率、手续费、中间行费用和预计到账时间的同屏比较。
- 用户自行标注“必要／可调整”支出，并在下一次体检中保留其判断。
- 基于盲测样本评估不同年龄用户是否能正确理解提示和确认边界。
