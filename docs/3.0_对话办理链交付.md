# TROPOS 3.0 对话办理链

日期：2026-10-27。实施分支：`codex/v3.0.0`；基线：`4e17723`。本轮在 3.0 的购物、跑腿适配、局域网访问和 Docker / Caddy 部署基础上增量修改，应用版本仍为 3.0.0。修改尚未发布到线上域名。

## 可办理的三条主线

| 主线 | 可以在对话内完成什么 | 明确的边界 |
| --- | --- | --- |
| 订阅管理 | 列出登记订阅 → 选定一项 → 查看取消影响 → 准备取消方案 → 单独确认 → 查询原回执 → 按最新现金状态重算 | 不批量猜选，不把取消当退款；每个方案与特定订阅、账户版本和有效期绑定 |
| 智能转账 | 说明收款人与金额 → 同名关系澄清／补充缺少金额 → 生成草案 → 明确更正金额 → 撤销旧草案 → 单独确认新草案 → 原回执查询 | 文本“确认”只展示核对卡；已记账转账不能改成新付款；不支持的表达继续澄清 |
| 账单分析 | 分类统计和流水依据 → 指定房租、水电或还款 → 展示已登记金额与到期日 → 查看现金影响 → 继续安排 | 当前可见样本不是完整月报；规则线索不是欺诈结论；查询不自动支付账单 |

完整银行办理链的授权、记账和回执均来自服务端。浏览器不把本地模拟结果冒充服务端成功。

## 建议体验

1. 启动 `./scripts/run.sh`，选择阿林并完成画像。模拟工资延期，保留当前现金缺口。
2. 在“银行助手”输入“查看有哪些会员快续费”，选择一项“比较取消影响”。
3. 点击“准备取消方案”，核对本窗口少支出、最低点改善和仍存在的缺口。
4. 可勾选聊天下方的取消超时演示。点击“核对并确认取消”，再单独确认这一项。
5. 查看原取消回执与最新现金状态，点击“按现在重新安排”。
6. 切到现金允许的陈工，输入“给王磊转100元”，选择同事，再输入“改成200元”。旧草案应显示撤销，只在新草案上保留确认入口。
7. 单独确认新草案；刷新或点击“恢复办理记录”，核对当前事项和原回执。

已完成的真实浏览器订阅示例：阿林工资延期，取消 ¥18 云音乐续费后，当前余额仍为 ¥20,000，最低预测余额从 ¥5,476 变为 ¥5,494，现金底线 ¥8,000 保留，缺口从 ¥2,524 变为 ¥2,506。超时按原方案查询到同一回执，没有另建取消请求。这只是该合成账户的结果。

转账浏览器示例：陈工说“给王磊转100元”，明确选择同事后，再说“改成200元”。旧卡片显示撤销，确认按钮移除；新卡片单独确认后，余额从 ¥20,000 变为 ¥19,800，仅有一笔对应交易。刷新后仍停留在陈工账户，恢复金额 ¥200 的已执行事项，不再返回可执行确认凭证。随后切回阿林追问房租，显示其本人账单详情；390 像素视口无横向溢出，页面没有跨域资源请求。

## 状态、恢复与更正

- 每段对话按模拟账户保存，记录最近 80 条消息及明确的办理对象。切换账户清空当前显示，再恢复该账户的记录；刷新使用上次成功选定的账户。
- 未决消息保留原 `requestKey`。断网或服务端结果未知时，使用原消息与凭证重试；恢复历史不会擅自判定未决请求失败。
- 重复消息凭证返回原事项。相同对话版本的并发修改只接受一个；不同服务实例之间也检查版本。
- 对话记录、请求记录和本轮草案创建在同一个 SQLite 写事务中提交；任何一步失败时回滚，避免留下重复或游离的可执行草案。
- 金额更正在事务中生成新草案并撤销旧草案，旧确认凭证不能再执行。切到其他话题后的裸“改成200元”不会更正先前转账。
- 订阅确认凭证有效 600 秒，确认前复核账户版本和订阅状态。已执行重放只返回原回执；过期、撤销和失效的方案不能确认。
- 历史文字按记录显示；恢复的可操作卡片另从服务端重新读取当前状态，不从历史恢复旧确认凭证。

这些能力使用明确的对话状态与规则；模型仍只接收新用户消息，不接收账本、令牌或整段历史。系统没有声称具备任意多轮自然语言推理或后台自动执行能力。

## 3.0 兼容性

保留 `ShoppingService`、购物及官方跑腿路由、购物页面和客户端接口；保留 LAN 访问模式、公共 Caddy 代理和 3.0 版本读取。补齐本地页面及字体资源路由，并将 `VERSION` 纳入 Docker 镜像复制清单，供 3.0 服务启动时读取。

旧的仅含 `message` 的单条 `/api/agent` 请求继续兼容；工作台使用带消息凭证与对话版本的新请求。历史固定意图评估不因此被包装为上下文能力或盲测成绩。
