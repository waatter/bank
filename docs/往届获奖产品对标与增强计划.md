# 从获奖案例到 TROPOS 的产品改进

调研时间：2026-10-22。下面分开记录公开证据、我们的判断和本轮实现。获奖记录不能代替产品性能、部署规模或真实用户收益的证明。

## 一、先对准本届赛题

2026 国内人工智能赛道要求银行智能体通过自然语言理解意图、规划并执行业务，至少覆盖六类核心场景中的三类，主题同时强调安全和体验。官网没有在当前公开说明中给出可据以引用的详细评分权重，因此本项目不自造“创新占多少分”等规则。[本届赛事官网](https://fintechathon.g-ican.com/)

对 TROPOS 的判断：已有转账授权和生活规划基础，下一步应把账单分析与订阅管理做得更有依据、更容易找到，并能解释一次操作对未来现金的影响。以上是团队的产品取舍，不是官方评分结论。

## 三、对照发现的缺口与本轮实现

| 原有缺口 | 本轮补充 | 能观察到的结果 |
|---|---|---|
| 首屏重复策略与余额，订阅操作藏得较深 | 首页行动预览与独立“行动”入口 | 查看缺口、最近账单、需复核订阅、预计工资各自的理由与去向 |
| 聊天只说“已读取账单”，缺少实质统计 | 基于同一账户快照的服务端分析 | 对话直接给出可见流水笔数、出账构成、最低余额、剩余缺口与规则核对线索 |
| 曲线难以追问“为什么这一天最低” | 可按日查看现金与到期事件 | 账单、续费和未到账收入有来源标识；日常预算仍按原设置计入 |
| 取消订阅前只显示费用，影响不清楚 | 每项订阅的单独反事实路径 | 比较取消后的最低余额、改善金额与仍存在的缺口，再决定是否确认取消 |
| 容易将取消续费当成已经赚到钱 | 按本窗口一次续费统计预计少支出，附取消回执 | 今天余额不增加，不假装退款、不年化为现实收益，不自动存入目标 |
| 缺少可以带走核对的决策材料 | 下载现金行动单 | 保留账户与数据版本、观察范围、假设、下一步和取消回执；文件本身不是执行授权 |
| 流水页面有固定异常数量与固定备注金额 | 按当前记录计算线索，显示原金额 | 没有线索就显示实际数量；历史样本不包装成完整月报 |

服务端 `GET /api/insights` 在同一个只读事务内检查读取同意、获取快照与计算；金额使用整数分，不写交易。读取后的账户快照通过既有工作台流程更新本地版本。前端对账户切换、版本变化和加载失败清除旧操作与旧下载入口。

订阅反事实每次只讨论一项：如果其下次续费在第 1–30 天内，从续费日开始将该笔费用加回原现金路径，重新寻找全窗口最低点。最低点不一定发生在原来的日期，所以最低余额改善不一定等于订阅费。今日现金与未受影响日期不变，余下缺口继续展示。

已取消项的结果来自持久化订阅状态及取消回执；它反映取消后的计划性少支出，不是已到账收入。历史出账含还款与调拨，分类统计不当作消费总额。工资依旧只是预计收入，到账事件后才成为当前余额。

## 四、尚需继续补的关键能力

1. **独立任务评估。**现有已知规则用例不能证明模型泛化。应另外收集未参与开发的口语表达、歧义收款人、跨句更正和失败恢复任务；支持前不能把聊天历史更正包装为已完成。
2. **完整用户演示验收。**需要实际浏览器完成建档、冲击、生活安排、取消、转账确认与重启恢复，并检查窄屏。新增行动页本轮完成静态审阅，未运行新增自动检查或浏览器流程，不沿用上一版通过数冒充本轮验收。
3. **真实用户证据。**访谈与小规模使用后再判断用户是否更容易理解缺口、完成任务和纠正假设。当前没有现实用户效果或因果收益证据。
4. **银行接入与部署。**卡片、理财申赎、外部商户预订仍未实现；账户选择是模拟登录。本机 SQLite 和私有源码仓库不等同于共享银行云服务。

## 五、下一次展示的主线

选择阿林并确认画像 → 打开“行动”看到账本依据 → 模拟收入延期 → 重读现金缺口与日历 → 比较一个订阅取消前后的现金路径 → 用户明确确认取消 → 核对回执及仍存在的缺口 → 进入生活规划继续安排 → 需要转账时另行生成并确认草案。

这个展示应使用运行时实际数字。订阅费很小时，只能减少很小的缺口；必要支出和现金底线不随展示目标变动。单次操作不能解决的缺口应继续保留。
